# AI에게 먼저 읽히기 — 화학 수업 슬라이드 제작 묶음

이 묶음으로 2022 개정 고등학교 「화학」·「물질과 에너지」·「화학 반응의 세계」 수업용 HTML 슬라이드 덱을 만든다. 아래 순서대로 한다. 명령은 AI가 직접 실행하고, 선생님이 해야 할 일이 생기면 그때 짧게 알린다.

## 1. 처음 한 번 (작업 환경 준비)

1. 이 파일, `README.md`, `docs/슬라이드_제작도구_가이드라인_화학.md`, `차시자료/_소스/작업지시/공통.md`, `차시자료/_소스/작업지시/화학3과목_공통_약속.md`를 읽는다.
2. 선생님이 알려 준 **과목 키**(`화학_미래엔`, `화학_비상`, `물질과에너지_미래엔`, `물질과에너지_비상`, `화학반응의세계_미래엔`, `화학반응의세계_비상`)의 과목 약속(`작업지시/<과목>_약속.md`)과 `덱목록.json`의 그 항목을 읽는다.
3. 프로그램 확인: `python --version`(3.x), `node --version`(20 이상), Chrome 실행 파일 위치. Python 패키지 `pillow`가 없으면 설치한다(`pip install pillow`, 가능하면 `pymupdf`도). Chrome이 Windows 기본 경로가 아니면 실행 파일을 찾아 환경 변수 `CHROME`으로 쓴다. 설치·권한이 필요하면 선생님에게 알린다.
4. 교과서·지도서 PDF: 선생님이 준 PDF를 `차시자료/_소스/_자료/`에 **덱목록.json의 `textbook`·`guide` 파일 이름으로 복사**한다(원본 이름은 그대로 두고 복사본을 만든다). 어느 PDF가 어느 단원인지는 첫 쪽 텍스트로 확인한다. 빠진 PDF가 있으면 목록으로 알린다.
5. 쪽별 텍스트: `차시자료/_소스/tools`에서 단원마다
   `python extract_pages.py "../_자료/<파일>.pdf" "../_추출/<파일>.txt" --offset=<덱목록의 pdfOffset>`
   (지도서는 `guideOffset`, 값이 없으면 0). 이미 있으면 건너뛴다.
6. 동작 확인: `python build.py 물리학/1-1-1` → `node render.mjs "../../물리학/1-1-1_평형과_안정성.html" "../_render/_확인" --slides=1-3` 이 오류 없이 끝나는지 본다(본보기 물리 덱). 확인한 뒤 `_render/_확인`은 지운다.

## 2. 덱 하나 만들기 (덱마다 반복)

선생님이 `<과목 키>/<덱 id>`(예: `화학_미래엔/2-2-2`)를 말하면 `공통.md`의 절차를 이 순서로 따른다.

1. **[구성안]** `plan.md` 작성 — 화면 문장 전문, 반응식·계산 검산, **필수 탐구 이행 절**(덱목록의 `requiredInquiry`는 반드시 실험실 + 탐구 슬라이드로), 범위 점검, 확인이 필요한 점. 끝나면 선생님에게 확인이 필요한 점만 짧게 묻는다.
2. **[제작]** `meta.json`·`slides.html`·`labs.js`·`extra.css` 작성 → 빌드 → 자동 점검 0건·콘솔 오류 0건 → 캡처로 확인 → 움직임·질문 강조 점검.
3. **[검토+수정]** 내용·화면 두 관점으로 스스로 엄격하게 검토하고(검토 파일 저장) 고친다.
4. **보고**: `공통.md` 5절 형식(장수, 점검 건수, 반응식 검산, 필수 탐구 이행, 교사 확인 필요, 엔진 문제). 결과 파일은 `차시자료/<과목 키>/<folder>.html`.

## 3. 지킬 것

- **고치지 않는 것**: `차시자료/_소스/engine/*`, `차시자료/_소스/tools/*`, 다른 덱 폴더, 물리 본보기 덱. 엔진·도구 문제는 고치지 말고 보고한다.
- 고치는 것: `차시자료/_소스/content/<과목 키>/<덱 폴더>/` 안의 파일과 `작업지시/검토/` 검토 파일만. 빌드 결과 HTML은 손으로 고치지 않는다.
- 교과서 그림·사진은 복사하지 않고 직접 그린 SVG로. 교과서 문장을 길게 베끼지 않는다.
- 화학식은 모두 `\ce{}`. 반응식은 원자 수·전하를 검산한다.
- 성취기준 <탐구 활동>은 필수다(가이드라인 S12).
- 선생님이 할 일(PDF 넣기, 프로그램 설치 허락, 내용 판단)이 생기면 그때 알리고, 그 밖의 명령은 직접 실행한다.

## 4. 웹사이트 배포 (Firebase — 관리자가 웹에서 글자·수식 수정)

사이트 구성: `차시자료/index.html`(덱 목록) · `view.html`(수업 화면, 웹 수정본이 있으면 그것을 보여 줌) · `edit.html`(관리자 전용 수정 화면) · `js/`·`css/`. 저장은 Firebase Realtime Database의 `decks/`(덱별 슬라이드 HTML), `meta/`(수정 표시), `backups/`(이전 저장본). 사이트 코드(`index.html`, `view.html`, `edit.html`, `js/fb.js`, `js/deckio.js`, `css/`)와 엔진은 고치지 않는다.

1. **바꾸는 파일은 둘뿐**: `차시자료/js/config.js`(선생님이 준 firebaseConfig 값을 그대로, `ADMIN_EMAILS`에 관리자 이메일) · `database.rules.json`(`'관리자@gmail.com'` 네 곳을 관리자 이메일로 — 관리자가 여럿이면 `auth.token.email == 'a' || auth.token.email == 'b'`).
2. Firebase 콘솔에서 선생님이 할 일이 남아 있는지 확인하고, 있으면 그때 알린다: ① Authentication → 로그인 방법 → **Google 사용 설정** ② **Realtime Database 만들기**(만든 뒤 콘솔에 보이는 주소가 `databaseURL`과 같아야 함) ③ Hosting은 `firebase deploy`가 처리.
3. Firebase CLI: `firebase --version`이 없으면 `npm install -g firebase-tools`. `firebase login`(선생님이 브라우저에서 구글 로그인 — 그때 알린다) → `firebase use --add`로 config의 `projectId`를 고른다(또는 `.firebaserc`를 만든다).
4. 덱 목록 만들기: `cd 차시자료/_소스/tools && python site_index.py` → `차시자료/decks.json`. 덱을 새로 빌드할 때마다 다시 실행하고 다시 배포한다.
5. 묶음 폴더(firebase.json이 있는 곳)에서 `firebase deploy` (Hosting + Database 규칙). `_소스/`(원본·PDF)는 firebase.json의 ignore로 올라가지 않는다 — 배포 뒤 목록에 PDF·plan.md가 없는지 확인.
6. 배포 주소(`https://<projectId>.web.app`)를 알리고, 선생님이 관리자 로그인 → 덱 「수정」 → 글자 고치기 → 「저장」 → 「수업 열기」에서 반영되는지 확인하게 한다.
7. **주의 — 같은 Firebase 프로젝트에 다른 사이트(예: 방탈출 게임)가 이미 배포되어 있으면** 그 프로젝트에 그대로 배포하지 말고 선생님에게 알린다(덮어씀). 새 Firebase 프로젝트를 쓰거나, 같은 프로젝트에 Hosting 사이트를 하나 더 만들어 `firebase.json`에 `"site"`를 지정한다.
8. 시험만 해 볼 때: 배포 없이 `차시자료`에서 `python -m http.server 8000` → `http://localhost:8000/index.html?local` (시험 모드, 이 브라우저에만 저장).

### 웹 수정본과 Claude Code 수정이 겹칠 때
웹에서 고친 덱을 Claude Code로 다시 빌드하면 웹 수정본이 새 원본을 가린다(수정 화면에 경고가 뜬다). 웹 수정본이 있는 덱(목록의 「웹 수정본」 표시)을 Claude Code로 고치기 전에는 선생님에게 수정 화면의 「수정본 내려받기」 파일을 받아 `content/<과목 키>/<덱>/slides.html`에 그 변경을 합치고, 빌드·배포한 뒤 웹에서 「원본으로 되돌리기」를 하게 안내한다.
