# 차시 덱 작업 지시서 (에이전트 공통 — 고등학교 화학 3과목)

이 문서는 2022 개정 교육과정 고등학교 「화학」, 「물질과 에너지」, 「화학 반응의 세계」 수업용 슬라이드 덱을 만들고 다듬는 에이전트가 따르는 공통 지시서다. 덱마다 맡는 일(구성안, 제작, 움직임, 검토, 수정)은 에이전트를 부를 때 따로 알려 준다.

경로 약속: `ROOT` = 이 묶음을 푼 폴더(`docs`와 `차시자료`가 들어 있는 곳), `SRC` = `ROOT/차시자료/_소스`

## 0. 덱 정보 찾기

- 과목 키 = `<과목>_<출판사>`: `화학_미래엔`, `화학_비상`, `물질과에너지_미래엔`, `물질과에너지_비상`, `화학반응의세계_미래엔`, `화학반응의세계_비상`. 교사가 쓰는 교과서의 키 하나만 쓴다.
- 덱 목록: `SRC/작업지시/덱목록.json` → `[과목 키].units[대단원]`(교과서·지도서 파일, 쪽 대응 `pdfOffset`·`guideOffset`, 주의 사항)과 `[과목 키].decks[]`(id, unit, folder, title, header, bookPages, standard, idPrefix, withUnitIntro, review, scope, split, note).
- 과목 약속: `SRC/작업지시/화학3과목_공통_약속.md`(세 과목 공통: id·data-sec·표식 클래스·색·입자 크기·표기·상수·탐구 슬라이드·덱 끝 마무리·분량·검산 형식) + `SRC/작업지시/<과목>_약속.md`(`화학_약속.md`, `물질과에너지_약속.md`, `화학반응의세계_약속.md`) — 표식 이름, data-sec 형식, 색·표기·상수, 범위 제한, 문항 배분, 덱 끝 마무리 형식. 출판사별 절이 따로 있다.
- 성취기준 원문: `ROOT/docs/교육과정_화학3과목_성취기준.md`
- 내용 폴더: `SRC/content/<과목 키>/<folder>/` — `plan.md`, `meta.json`, `slides.html`, `labs.js`, `extra.css`
- `meta.json` 형식: `{"title": "<title>", "file": "<folder>", "header": "<header>"}` — 값은 덱목록.json 그대로
- 결과 파일: `ROOT/차시자료/<과목 키>/<folder>.html` · 캡처 폴더: `SRC/_render/<과목 키>/<folder>/`
- 같은 대단원의 다른 덱 폴더가 이미 있으면 그 `plan.md` 앞부분의 "덱 공통 약속"과 `slides.html`을 읽고 용어·기호·색·원자 크기·개념 지도 이어가기를 맞춘다.

## 1. 작업 환경

- 엔진의 구현·규칙 요약: `SRC/AUTHORING.md` (가이드라인 규칙 T·M·C·D·S의 구현 방법)
- 교과서·지도서 PDF는 `SRC/_자료/`에 덱목록.json의 파일 이름으로 둔다. 쪽별 텍스트는 `cd "SRC/tools" && python extract_pages.py "../_자료/<파일>.pdf" "../_추출/<파일>.txt" --offset=<pdfOffset>`로 만든다(이미 있으면 다시 만들지 않는다). 머리줄 `=== p.<PDF쪽> (책 <쪽>쪽) ===`을 Grep으로 찾아 offset/limit로 읽는다.
- 빌드: `cd "SRC/tools" && python build.py <과목 키>/<folder>`
- 점검·캡처: `cd "SRC/tools" && node render.mjs "../../<과목 키>/<folder>.html" "../_render/<과목 키>/<folder>"` (일부만: `--slides=3,5-8`)
  - 단계별 캡처(`--steps`)는 반드시 하위 폴더로: `"../_render/<과목 키>/<folder>/steps"` (render.mjs는 시작할 때 출력 폴더의 s*.png를 지운다)
  - 헤드리스 Chrome 경로가 Windows 기본값과 다르면 환경 변수 `CHROME`에 실행 파일 경로를 준다.
- **캡처 모음**: `cd "SRC/tools" && python sheet.py "../_render/<과목 키>/<folder>"` (일부만 `--slides=3-10`, 단계별은 `--steps`) → 슬라이드 4장을 한 장(2×2)에 모은 `sheet_NN_MM.png`. 전체 훑어보기는 이것으로 하고(사용량 1/4), 자세히 볼 슬라이드만 원본 `sNN.png`를 본다. Pillow가 필요하다.
- 움직임·질문 강조 점검: `node motion_check.mjs <과목 키>/<folder>`, `node ask_check.mjs <과목 키>/<folder>` — 덱 이름 일부만 줘도 되지만, 출판사가 다른 같은 번호 덱이 있으면 과목 키까지 준다.
- 캡처 PNG와 교과서 PDF 쪽은 Read 도구로 이미지로 본다. PDF가 Read로 안 열리면 PyMuPDF(`import fitz`) 또는 `pdftoppm -f N -l N -r 80 -png`로 쪽을 PNG로 만들어 본다.
- **추출 텍스트의 기호 깨짐**: 가역 화살표 ⇌ → `^jjj&`·`1ÚÖ`, × → `_`, ℃ → `¾`, 아래·위 첨자가 떨어져 나옴(`Na CO` + 따로 `2 3`), δ → `d`, Δ → `D`. 화학식·반응식·수치는 **반드시 PDF 쪽 이미지로 확인**하고 옮긴다.
- 실험실 버튼 동작을 확인하는 임시 스크립트는 scratchpad의 **덱 이름 하위 폴더**에 둔다(다른 에이전트와 파일 이름이 겹치지 않게).
- 고치지 않는 것: 엔진(`engine/*`), 도구(`tools/*`), 다른 덱 폴더. 엔진 문제를 찾으면 고치지 말고 보고한다.
- 교과서 그림·사진은 복사하지 않고 직접 그린 SVG로 바꾼다. 교과서 문장을 길게 베끼지 않는다.

## 2. 먼저 읽을 것 (구성안·제작 단계)

- 최상위 규칙 `ROOT/docs/슬라이드_제작도구_가이드라인_화학.md` (전부 — 특히 2장 하우스 규칙, 2.3 화학식 C1–C12, 2.4 도식 D21–D30, 2.5 색, 10장의 해당 과목 팩)
- `SRC/AUTHORING.md` (전부)
- `SRC/작업지시/화학3과목_공통_약속.md` (전부) + 과목 약속 `SRC/작업지시/<과목>_약속.md` (공통 절 + 해당 출판사 절)
- 엔진 사용 본보기(코드 형식 참고): `SRC/content/물리학/1-1-1_평형과_안정성/` — **물리 덱**이므로 내용·색 뜻은 따르지 않고, 슬라이드 구조(표지·목표·도입·개념·단계 공개·예제·스스로 평가·마무리), `data-anim` 움직임, `.blank`·`.answer`·`.board`·실험실 코드 꼴만 본다. slides.html은 앞 300줄 정도와 필요한 패턴만 Grep으로, labs.js는 실험실 한 개만 읽는다. 품질 본보기 캡처가 필요하면 `ROOT/차시자료/물리학/1-1-1_평형과_안정성.html`을 render.mjs로 캡처해 s02·s05·s08·s11·s17·s22번을 본다(구성 밀도·그림 수준·문체의 기준).
- 같은 과목·대단원에서 먼저 만든 화학 덱이 있으면 그것이 본보기보다 우선이다.
- [구성안]·[검토-내용]: 덱목록의 단원 자료(교과서·지도서 추출 텍스트)에서 **이 덱이 다루는 쪽만** 읽는다(쪽 머리줄을 Grep으로 찾아 offset/limit). 지도서는 "교과서 N 쪽" 표시를 Grep으로 찾는다. [제작]은 교과서를 다시 읽지 않는다 — plan.md에 화면 문장이 다 있다(그림·화학식 모양을 확인해야 할 쪽만 PDF 이미지로 본다).

## 3. 할 일별 절차

### [구성안]
`plan.md`를 작성한다. 이미 있으면 먼저 읽고 빠진 슬라이드 절만 이어서 끝까지 완성한다(처음부터 다시 쓰지 말 것).
- 맨 앞: 덱 정보(폴더, meta.json, 범위 쪽, 쪽 대응, 성취기준 코드와 문장, 총 장수와 구성) + 덱 공통 약속 표(data-sec 형식, 개념 번호, 표식, 용어·화학식·수식 표기, 상수 값, 색, 원자 반지름(원소별 px), id 접두어, 개념 지도 이어가기)
- 각 슬라이드: 번호, 템플릿(가이드라인 3.3), data-sec, data-title, h2 제목·표식, **화면에 들어갈 실제 문장·화학식(`\ce{}`)·수식(LaTeX)·문항·정답 전문**, 단계 공개(.step / data-g), 그림(배치·라벨·색·원자 수), 실험실 명세(입력·계산식·표시값·애니메이션), 근거 쪽(교과서·지도서)
- **필수 탐구(S12)**: 덱목록의 이 덱 `requiredInquiry`(성취기준 <탐구 활동>)를 먼저 확인한다. 각 탐구마다 plan.md에 **탐구 이행 절**을 둔다 — 성취기준 탐구 활동 원문, 교과서 활동(쪽)과 겹치는 부분·빠진 부분, 실험실 명세(조작 변인 슬라이더·측정값 표·그래프·해석 문장·오차 처리), 탐구 슬라이드 묶음(S7 순서 + 안전 S9), 탐구 활동 문장의 동사 하나하나가 어느 슬라이드·조작에서 일어나는지 대응표. 교과서가 일부만 다루면 덱이 채운다. 실험실과 탐구 슬라이드 둘 다 필수다.
- 교과서의 모든 내용·활동(탐구·해 보기·확인하기·연습 해 보기·자료 읽기·과학 마당·이야기·화학과 나의 미래 등 — 과목 약속 3절의 표식 목록)·예제·문항을 빠짐없이 넣고, 지도서의 지도 내용(지도 방안, 지도상의 유의점, 오개념, 예시 답안, 평가 기준, 참고 자료)을 발문·단계 공개·정답에 반영한다. 새 개념 앞 연결(S5), 거시 → 미시 → 기호(S10), 한 장에 한 문항(S2), 과정은 단계 카드(S3), 실험 안전(S9)
- **반응식 검산 절**: 덱에 나오는 모든 화학 반응식·반쪽 반응식을 모아 원소별 원자 수와 전하 합을 적는다(C5). 모든 계산 문항의 풀이를 다시 계산해 적는다(교과서·지도서 정답과 다르면 그 사실과 근거).
- **범위 점검 절**: 가이드라인 10장의 범위 제한과 지도서 「지도상의 유의점」에 걸리는 내용이 없는지 한 줄씩.
- 마지막 절: 확인이 필요한 점(unresolved)

### [제작]
`plan.md`를 따라 `meta.json`, `slides.html`, `labs.js`(실험실 — `API.loop`로 움직이는 시뮬레이션), 필요하면 `extra.css`를 작성하고 빌드한다. 이미 `slides.html`이 있으면 이어서 완성한다(plan.md가 없거나 미완성이면 [구성안]부터).
- plan.md의 탐구 이행 절대로 필수 탐구 실험실을 빠짐없이 만든다. 실험실은 조작마다 결과가 실제로 달라지고, 측정값 표와 그래프가 쌓이는지 실험실 시험 스크립트로 확인한다.
- 화학식·이온·반응식은 모두 `$\ce{…}$`(본문)·`data-tex="\ce{…}"`(그림)로 쓴다. 원자 모형은 `data-atom`(같은 원소는 덱 안에서 같은 반지름).
- render.mjs로 점검·캡처하여 **자동 점검 0건(C1 포함)·콘솔 오류 0건**까지 고친다.
- 몇 장씩 쓸 때마다 `--slides=`로 그 슬라이드만 캡처해 원본으로 확인하며 진행한다. 다 쓴 뒤 전체를 캡처 모음(sheet.py)으로 빠짐없이 보고(전체 보기 2회: 완성 직후·최종), 그림·실험실이 복잡하거나 문제가 의심되는 슬라이드는 원본 sNN.png로 자세히 본다. 겹침·잘림·끊긴 도선·전자점 배치·결합각·대칭·어색한 배치·빈 공간을 고친다.
- 단계가 겹치는 슬라이드는 `--steps`(하위 폴더)로 공개 순서를 확인한다.
- **움직임(가이드 6.4)**: 그림에 `data-anim`으로 화학 이해를 돕는 움직임을 넣는다(그린 모습 = 마지막 모습, 원자 보존·전자 이동 방향 등 화학적으로 맞게, 덱마다 15–25곳). 점검 `node motion_check.mjs <과목 키>/<folder>`와 `?motion` 중간 프레임 캡처.
- **질문 강조(가이드 6.5)**: 답 단계 앞의 질문 문장에는 '?'를 쓰거나 'Q'로 시작한다. 점검 `node ask_check.mjs <과목 키>/<folder>` 0건.

### 웹 수정본이 있는 덱
웹사이트(`AI에게_먼저_읽히기.md` 4절)에서 관리자가 고친 덱은 웹 수정본이 원본을 가린다. [제작]·[수정]으로 이미 배포된 덱을 다시 빌드하기 전에 선생님에게 웹 수정본이 있는지 묻고, 있으면 「수정본 내려받기」 파일을 받아 그 변경(글자·수식)을 `slides.html`에 합친 뒤 빌드한다. 보고에 "웹 수정본 합침: 있음/없음"을 적는다.

### [움직임] (이미 있는 덱에 그림 움직임 넣기)
가이드 6.4·6.5를 보고, 원본 `slides.html`의 정적 SVG에 `data-anim`을 넣는다(실험실·엔진은 그대로). 글이 많은 장은 내용을 바꾸지 않고 설명 문장을 한두 단계로 나누는 정도만 허용(결론·정답은 끝에). 빌드 → `render.mjs` 자동 점검 0·콘솔 0(그린 모습 그대로인지) → `motion_check.mjs` 0 → `ask_check.mjs` 0 → 몇 장은 `?motion` 중간 프레임을 `_render/동작_후/<과목 키>/<folder>/frames/`에 남긴다.
- 움직이는 입자에 붙은 라벨·화살표(이온의 전하, 쌍극자 화살표, $e^-$)는 입자와 같은 묶음에 넣어 함께 움직이게 한다(가이드 6.4 M-D). 반응 전후 재배열 움직임은 원자 수가 보존되게 같은 `data-atom`을 옮긴다.

### [검토-내용] (파일을 고치지 않는다)
화학 교사·교과서 검토자·국어 교정자로서 본다. 화면 디자인은 보지 않는다.
- 교과서(·지도서) 해당 쪽을 읽고, 모든 개념·정의·탐구·활동·예제·확인·문항이 빠짐없이 정확히 들어갔는지 대조한다(빠지면 high).
- **필수 탐구(S12)**: 이 덱의 `requiredInquiry` 하나하나가 실험실 + 탐구 슬라이드로 이행되었는지, 탐구 활동 문장의 모든 동사가 실제로 일어나는지 확인한다(빠지거나 일부만 이행되면 high).
- **모든 화학 반응식의 원자 수·전하·상태 기호·계수를 직접 검산**하고(C2·C5), 모든 수치·단위·유효 숫자·계산·정답·해설을 다시 풀어 검증한다. 실험실 `labs.js` 계산식도 코드로 확인한다.
- 화학식·물질 이름이 교과서 표기와 같은지(C6, 예: 전기음성도·몰농도 붙여쓰기, 대한화학회 이름) 확인한다.
- 그림의 화학(입자 모형의 원자 수 보존 D21, 루이스 전자점 수와 옥텟 D22, 분자 구조 이름·결합각 D23, 쌍극자 화살표 방향 D24, 그래프 축 D4·D25, $\Delta H$·$E_\mathrm{a}$ 방향 D26, 기구 모양 D27, 전지·전기 분해의 전자·이온 이동과 극 D28, 색 뜻 D7)을 캡처로 확인한다.
- 오개념 유발 표현(평형에서 반응이 멈춘다, 중화점은 항상 중성 등), 교육과정 범위 초과(가이드라인 10장, 지도서 「지도상의 유의점」 기준)를 찾는다.
- 수업 흐름: 단계 공개 순서(질문 → 생각 → 답, S1), 거시 → 미시 → 기호(S10), 한 장에 한 문항·판서 공간(S2), 단계 카드(S3), 새 개념 앞 연결(S5), 실험 안전(S9), 활동 지시문의 실행 가능성.
- 한국어: 맞춤법·띄어쓰기·번역투·긴 문장·용어 일관성(교과서 표기).

### [검토-화면] (파일을 고치지 않는다)
디자인 검수자로서 본다. 화학 내용 판단은 하지 않는다.
- 캡처 폴더의 모든 sNN.png를 원본으로 한 번 본다(한 메시지에 6–8장씩 동시에 Read — 화면 검토는 자세히). 단계가 겹치는 슬라이드는 `--steps`(하위 폴더) + `sheet.py --steps` 모음으로 본다.
- 겹침·잘림·넘침·끊긴 도선·비대칭이면 안 되는 그림(대칭 분자, 전자점 배치)·지나친 빈 공간/쏠림·빽빽함·19px 미만 본문·화면에서 18px 미만으로 보이는 그림 라벨(원자 기호 포함, AUTHORING.md 5.1)·정답 가운데 정렬을 본다.
- T1–T5, M1–M6·M9, C1–C4, D1–D8, D21–D24를 slides.html 코드와 캡처 양쪽에서 확인한다(유니코드 첨자, 본문 글자 화학식, 가운뎃점, 단위 위치, 축 라벨 형식, id 고유, 색 의미, 원자 색·크기 일관성).
- 본보기 덱보다 수준이 떨어지는 슬라이드(그림 빈약, 글만 많음)를 찾는다.

검토 결과는 `SRC/작업지시/검토/<과목 키>_<id>_content.json` 또는 `<과목 키>_<id>_visual.json`에 다음 형식으로 저장한다:
`{"findings":[{"slide":3,"severity":"high|medium|low","rule":"C5","problem":"…","fix":"…"}],"summary":"…"}`

### [수정]
지시받은 검토 파일의 지적을 하나씩 교과서·지도서·AUTHORING.md·캡처로 직접 확인하고, 맞는 것만 반영한다(틀린 지적은 이유와 함께 기각). high·medium은 모두 판단해 처리하고, low도 쉽게 개선되면 반영한다.
- 고치는 동안에는 `--slides=`로 바꾼 슬라이드만 캡처해 원본으로 확인한다. 다 고친 뒤: 빌드 → render.mjs(전체) → 자동 점검 0건·콘솔 오류 0건 → **전체를 캡처 모음(sheet.py)으로 빠짐없이 최종 확인**하고(수정이 새 겹침·넘침을 만들지 않았는지), 고친 슬라이드는 원본으로 본다. 예제·스스로 평가·실험실·단계 카드 몇 장은 `--steps`로 공개 순서를 확인한다.
- 남은 문제는 직접 고친다. `plan.md` 끝에 반영 기록(반영/기각과 이유)을 덧붙인다.

### [검토+수정]
따로 검토 파일이 없거나 한쪽 관점만 있을 때. 먼저 지시받은 관점([검토-내용]·[검토-화면] 중 빠진 것)으로 스스로 꼼꼼히 검토해 `SRC/작업지시/검토/<과목 키>_<id>_<관점>.json`에 저장한 뒤, 이미 있는 검토 파일과 함께 [수정] 절차를 따른다. 제작자가 놓친 것을 찾는 것이 목적이므로, 덱을 처음 보는 사람의 눈으로 엄격하게 본다.

## 4. 사용량 아끼기 (꼭 지킨다)

사용량 한도가 빠듯하다. 대화가 길어질수록 도구 호출 한 번의 비용이 커지므로, **호출 횟수를 줄이고 읽는 양을 줄인다.**
- 서로 독립인 도구 호출은 **한 메시지에 여러 개를 동시에** 보낸다. 캡처 PNG는 한 메시지에 6–8장씩 동시에 Read한다. 여러 파일 읽기·Grep도 동시에.
- 전체 훑어보기는 캡처 모음(`sheet.py`, 4장을 1장에)으로 한다. 원본 sNN.png는 자세히 볼 슬라이드만.
- 큰 파일(plan.md·slides.html·교과서·지도서 텍스트)은 한 번만 읽는다. 다시 볼 때는 Grep으로 위치를 찾아 offset/limit로 필요한 부분만 읽는다. 지도서는 교과서보다 훨씬 길다 — 덱 범위의 "교과서 N 쪽" 주변만 읽는다.
- 수정하는 동안에는 `--slides=`로 바꾼 슬라이드만 다시 캡처해 확인하고, 전체 캡처는 마지막에 한 번(최종 확인) 한다. `--steps`도 필요한 슬라이드만.
- 편집은 모아서 한다: 한 슬라이드의 여러 수정은 Edit 한 번으로, 서로 다른 곳의 Edit는 한 메시지에 동시에. 반복되는 기계적 수정은 짧은 Python 스크립트 한 번으로.
- PDF 쪽 이미지는 그림·화학식 확인이 꼭 필요할 때만 본다(추출 텍스트의 화학식이 깨졌을 때는 꼭 본다).
- plan.md는 화면에 들어갈 문장·화학식·수식·정답은 전문으로 쓰되, 그림 명세는 좌표·라벨·색·원자 수 위주로 간결하게 쓴다(코드를 길게 붙여 넣지 않는다).
