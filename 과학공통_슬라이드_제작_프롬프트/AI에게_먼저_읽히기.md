# AI에게 먼저 읽히기 — 과학 수업 슬라이드 제작 묶음 (물리·화학·생명과학·지구과학 공통)

이 묶음으로 2022 개정 교육과정 **고등학교 「통합과학1」·「통합과학2」, 중학교 「과학1」·「과학2」·「과학3」**(필요하면 고등 물리학·화학·생명과학·지구과학 선택 과목) 수업용 HTML 슬라이드 덱을 만든다. 이 묶음은 **새 저장소·새 Firebase 프로젝트에서 처음부터 시작하는 출발 묶음**이다. 아래 순서대로 한다. 명령은 AI가 직접 실행하고, 선생님이 해야 할 일이 생기면 그때 짧게 알린다.

## 1. 처음 한 번 (준비)

### 1.1 읽기
이 파일, `README.md`, `docs/슬라이드_제작_가이드라인_과학공통.md`(1–8장 + 10장 영역 팩 목차), `차시자료/_소스/AUTHORING.md`, `차시자료/_소스/작업지시/공통.md`, `차시자료/_소스/작업지시/과학공통_약속.md`.

### 1.2 프로그램 확인
`python --version`(3.x — `python3`일 수 있음), `node --version`(20 이상), Chrome(또는 Edge) 실행 파일. Python 패키지 `pillow`(필수)와 `pymupdf`(PDF 쪽 이미지, 권장)가 없으면 설치한다. Chrome이 기본 경로(Windows Chrome·Edge, macOS `/Applications/Google Chrome.app`, Linux `google-chrome`·`chromium`)에 없으면 실행 파일을 찾아 환경 변수 `CHROME`으로 쓴다. 설치·권한이 필요하면 선생님에게 알린다.

### 1.3 자료 넣기 (선생님이 준 파일)
1. **교과서·지도서 PDF**를 `차시자료/_소스/_자료/`에 **복사**한다(원본 이름은 그대로 두고 복사본). 이름은 `<과목 키>_교과서[_권].pdf`, `<과목 키>_지도서[_권].pdf`(예: `통합과학1_〔출판사〕_교과서_1.pdf`). 어느 PDF가 어느 단원인지는 첫 쪽 텍스트로 확인한다. 빠진 것이 있으면 목록으로 알린다.
2. **교육과정 문서**(성취기준 PDF·HWP·문서)를 `차시자료/_소스/_자료/`에 복사하고, 그 과목의 내용 체계·성취기준·<탐구 활동>·성취기준 해설·적용 시 고려 사항을 `docs/교육과정_<과목>_성취기준.md`로 정리한다(통합과학 1·2는 하나로, 중학 과학은 하나로). **코드와 문장은 원문 그대로**, 지어내지 않는다. 문서가 없으면 선생님에게 받는다.
3. 쪽별 텍스트: `차시자료/_소스/tools`에서 `python extract_pages.py "../_자료/<파일>.pdf" "../_추출/<파일>.txt" --offset=<offset>`. offset(책 쪽 − PDF 쪽)은 PDF 두세 쪽을 이미지로 보고 인쇄된 쪽 번호로 정한다.

### 1.4 과목 키와 덱목록 만들기
1. **과목 키**를 정한다: `<과목>_<출판사>` — 예 `통합과학1_〔출판사〕`, `통합과학2_〔출판사〕`, `과학1_〔출판사〕`, `과학2_〔출판사〕`, `과학3_〔출판사〕`. 출판사 이름은 키·폴더에만 쓰고 **화면에는 쓰지 않는다**.
2. **과목 약속**: `작업지시/통합과학_약속_틀.md` 또는 `중학과학_약속_틀.md`를 복사해 `작업지시/<과목>_약속.md`로 만들고, 틀 끝의 「채우는 법」대로 교과서 차례·쪽·표식·범위 제한을 채운다.
3. **덱목록**: `작업지시/덱목록.json`의 `_필드` 설명대로 과목 키 항목을 만든다 — `units`(대단원·PDF·offset), `decks`(덱 하나 = 소단원 하나 + 대단원 마무리 덱, `area` 영역, `standard` 성취기준, `idPrefix`), `requiredInquiry`(성취기준 <탐구 활동> → 담당 덱). 예시 항목 `통합과학1_출판사`는 지운다.
4. `작업지시/진행상황.md`에 과목 키 절과 덱 표를 만든다(틀 그대로).
5. 덱목록을 **표로 선생님에게 보여** 덱 수·묶기·마무리 덱·범위 판단을 확인받는다.

### 1.5 동작 확인 (본보기 덱)
`차시자료/_소스/tools`에서 `python build.py 과학공통_본보기/0-0-1` → `node render.mjs "../../과학공통_본보기/0-0-1_과학_공통_본보기.html" "../_render/_확인"` 이 「KaTeX 로드됨 · 자동 점검 0건 · 콘솔 오류 0건」으로 끝나는지 본다. 확인한 뒤 `_render/_확인`은 지운다. (본보기 덱은 지우지 않는다 — 네 영역 그림·실험실의 코드 꼴 본보기다.)

### 1.6 Firebase 프로젝트 (웹사이트를 쓸 때 — 4절에서 해도 됨)
선생님이 **새 Firebase 프로젝트**를 만들고(4절 2), 그 값을 `차시자료/js/config.js`와 `.firebaserc`(`your-project-id` 자리)에 적는다. 이 묶음에는 어떤 프로젝트 값도 들어 있지 않다.

## 2. 덱 하나 만들기 (덱마다 반복)

선생님이 `<과목 키>/<덱 id>`(예: `통합과학1_〔출판사〕/1-1-1`)를 말하면 `공통.md`의 절차를 이 순서로 따른다. **한 번에 한 덱씩.**

1. **[구성안]** `plan.md` — 0절(덱 정보·성취기준·영역·덱 공통 약속), 장마다 **화면 문장 전문**·식·단계 공개·그림·실험실 명세, **필수 탐구 이행 절**(덱목록 `requiredInquiry`는 반드시 실험실 + 탐구 장으로), **검산 절**(계산·반응식·그래프·유전·지사), 범위 점검, **확인이 필요한 점**. 끝나면 선생님에게 확인이 필요한 점만 짧게 묻는다.
2. **[제작]** `meta.json`·`slides.html`·`labs.js`·`extra.css` → 빌드 → **자동 점검 0건·콘솔 오류 0건** → 캡처(sheet 모음)로 확인 → 실험실 PRE 시험 → `motion_check` 0 · `ask_check` 0.
3. **[검토+수정]** 내용·화면 두 관점으로 스스로 엄격하게 검토하고(`작업지시/검토/<과목 키>_<id>_content.json`, `_visual.json`) 고친다. 최종 캡처 모음으로 전체 다시 확인.
4. **보고**: `공통.md` 5절 형식. 결과 파일은 `차시자료/<과목 키>/<folder>.html`. 관리 도구로 기록: `python 차시자료/_소스/tools/관리/prog.py <과목 키> <id> ✅ <장수> 0 0 "<필수 탐구>" "<확인 필요>"`.

여러 덱을 하위 에이전트에게 맡길 때는 `작업지시/에이전트_안내_틀.md`를 복사해 `에이전트_안내.md`로 채우고(경로·자료 현황), 에이전트에게 그 파일을 먼저 읽게 한다.

## 3. 지킬 것

- **고치지 않는 것**: `차시자료/_소스/engine/*`, `tools/*`, `vendor/*`, 사이트 파일(`index.html`, `view.html`, `edit.html`, `js/fb.js`, `js/deckio.js`, `css/`), 다른 덱 폴더, 본보기 덱. 엔진·도구 문제는 고치지 말고 보고한다.
- 고치는 것: `차시자료/_소스/content/<과목 키>/<덱 폴더>/`, `작업지시/`(약속·덱목록·진행상황·검토), `docs/교육과정_*`, 그리고 배포 때 `js/config.js`·`database.rules.json`·`.firebaserc`. 빌드 결과 HTML은 손으로 고치지 않는다.
- 교과서 그림·사진은 복사하지 않고 직접 그린 SVG로. 교과서 문장을 길게 베끼지 않는다.
- **화면에 출판사 이름을 쓰지 않는다.** 성취기준 코드·쪽·정답을 지어내지 않는다.
- 식·단위는 LaTeX(`$…$`, `\text{}`), 화학식은 `\ce{}`, 유전자 기호는 기울임, 그래프는 계산값으로.
- 교과서·지도서 오류를 찾으면 덱에는 바른 값, 교과서 값은 작게 병기, plan.md 「확인이 필요한 점」에(과학공통 약속 12절).
- 지도서가 없으면 직접 만든 예시 답안·결과 예시를 「확인이 필요한 점」에 적고 멈추지 않는다.
- 성취기준 <탐구 활동>은 필수(가이드라인 S12).
- 사용량 한도로 멈추면 다음에 plan.md·slides.html·진행상황.md를 읽고 **빠진 곳부터 이어서** 한다.
- 선생님이 할 일(PDF 넣기, 프로그램 설치 허락, 내용 판단, Firebase 콘솔 작업)이 생기면 그때 알리고, 그 밖의 명령은 직접 실행한다.

## 4. 배포

### 4.1 Firebase 사이트 (기본 — 관리자가 웹에서 글자·수식 수정)
사이트 구성: `차시자료/index.html`(덱 목록, 과목 탭) · `view.html`(수업 화면, 웹 수정본이 있으면 그것) · `edit.html`(관리자 수정 화면, 구글 로그인) · `js/`·`css/`. 저장은 Realtime Database `decks/`·`meta/`·`backups/`.

1. **새 Firebase 프로젝트** — 선생님이 할 일(그때 알린다): ① Firebase 콘솔에서 프로젝트 만들기(이름 예: `science-slides-〔학교〕`) ② 웹 앱 추가(</>) → firebaseConfig 값 복사 ③ Authentication → 로그인 방법 → **Google 사용 설정** ④ **Realtime Database 만들기**(만든 뒤 보이는 주소가 `databaseURL`).
2. **바꾸는 파일은 셋**: `차시자료/js/config.js`(firebaseConfig 값을 그대로, `ADMIN_EMAILS`에 관리자 이메일 — 지금은 `you@example.com`) · `database.rules.json`(`you@example.com` 네 곳을 관리자 이메일로 — 여럿이면 `auth.token.email == 'a' || auth.token.email == 'b'`) · `.firebaserc`(`your-project-id`를 projectId로).
3. Firebase CLI: `firebase --version`이 없으면 `npm install -g firebase-tools` → `firebase login`(선생님이 브라우저에서 구글 로그인 — 그때 알린다).
4. 덱 목록: `cd 차시자료/_소스/tools && python site_index.py` → `차시자료/decks.json`(덱목록.json의 과목 키만, 탭 순서 = 덱목록 순서. 본보기까지 올리려면 `--all`).
5. 묶음 폴더(firebase.json이 있는 곳)에서 `firebase deploy`(Hosting + Database 규칙). `_소스/`·`완성본/`은 firebase.json의 ignore로 올라가지 않는다 — 배포 뒤 PDF·plan.md가 보이지 않는지 확인.
   - **완료(✅) 덱만** 올리려면 `bash 차시자료/_소스/tools/관리/deploy_done.sh [과목 키 순서…]`(진행상황.md의 ✅ 덱만 스테이징해 Hosting 배포, 탭 순서는 인자 → `관리/관리설정.json` → 덱목록 순서). `DRY=1`이면 스테이징만.
   - 덱 하나를 끝낼 때 기록·배포를 한 번에: `bash 차시자료/_소스/tools/관리/gdone.sh <과목 키> <id> "<보고 한 줄>"`.
6. 배포 주소(`https://<projectId>.web.app`)를 알리고, 선생님이 관리자 로그인 → 덱 「수정」 → 글자 고치기 → 「저장」 → 「수업 열기」에서 반영되는지 확인하게 한다.
7. **주의**: 같은 Firebase 프로젝트에 다른 사이트가 이미 배포되어 있으면 그대로 배포하지 말고 알린다(덮어씀). 새 프로젝트를 쓰거나, Hosting 사이트를 하나 더 만들어 `firebase.json`에 `"site"`를 지정한다.
8. 배포 없이 시험: `차시자료`에서 `python -m http.server 8000` → `http://localhost:8000/index.html?local`(시험 모드, 이 브라우저에만 저장). config.js에 「여기에」 값이 남아 있으면 자동으로 시험 모드다.

**웹 수정본과 다시 빌드가 겹칠 때**: 웹에서 고친 덱을 다시 빌드하면 웹 수정본이 새 원본을 가린다(수정 화면에 경고). 그 덱을 고치기 전에 선생님에게 「수정본 내려받기」 파일을 받아 변경을 `slides.html`에 합치고, 빌드·배포한 뒤 웹에서 「원본으로 되돌리기」를 하게 안내한다.

### 4.2 오프라인 HTML 파일 (선택)
인터넷이 불안한 교실·USB용. 덱마다 `python build.py <과목 키>/<id> --offline` → `차시자료/완성본/<과목 키>/<folder>.html`(KaTeX·mhchem·글꼴을 파일 안에 넣어 약 1–1.5 MB). `node verify_offline.mjs "../../완성본/<과목 키>/<folder>.html"` → OK(외부 요청 0·KaTeX 오류 0·점검 0)를 확인한다. 본문 글꼴은 만들 때만 인터넷이 필요하다(못 받으면 경고 후 기본 글꼴). 덱이 여럿이면 `python site_index.py --목록` → `차시자료/목록.html`(완성본 폴더와 함께 옮김). 받을 파일의 경로와 크기를 표로 알린다.
