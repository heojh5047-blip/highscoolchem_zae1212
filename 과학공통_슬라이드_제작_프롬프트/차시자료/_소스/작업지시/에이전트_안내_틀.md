# 덱 제작 에이전트 공통 안내 (틀 — 반드시 끝까지 읽기)

> **이 파일은 틀이다.** 여러 덱을 차례로(또는 하위 에이전트에게 나눠) 만들 때, 관리하는 AI가 복사해 `에이전트_안내.md`로 두고 〔 〕 자리(경로·이 환경의 사정)를 채운다. 덱을 맡은 에이전트는 이 파일을 **처음부터 끝까지** 읽고 따른다. 아래 규칙은 고등학교 화학 4과목 90덱을 만들며 실제로 생긴 문제에서 나온 것이다.

ROOT = 〔묶음 폴더 절대 경로〕, SRC = `ROOT/차시자료/_소스`, WORK = 〔임시 작업 폴더, 예: scratch/<과목 키>_<id>/〕

## 할 일
맡은 덱 **하나**를 `ROOT/AI에게_먼저_읽히기.md` 「2. 덱 하나 만들기」대로 **[구성안] → [제작] → [검토+수정]** 끝까지 마친다. 규칙은 `SRC/작업지시/공통.md`(전부), `SRC/작업지시/과학공통_약속.md`, `SRC/작업지시/<과목>_약속.md`, `SRC/AUTHORING.md`, `ROOT/docs/슬라이드_제작_가이드라인_과학공통.md`(2·3·5·6.4·6.5·7·8장과 10장의 해당 영역 팩), `ROOT/docs/교육과정_<과목>_성취기준.md`. 덱 정보는 `SRC/작업지시/덱목록.json`.

## 1. 교과서 PDF 대조와 쪽 offset 확인
1. 교과서 PDF는 `SRC/_자료/`, 쪽별 텍스트는 `SRC/_추출/<같은 이름>.txt`(머리줄 `=== p.N (책 M쪽) ===`). 없으면 `extract_pages.py`로 만든다.
2. **offset을 믿기 전에 확인한다**: 덱 범위 첫 쪽과 끝 쪽을 `pdftoppm -f N -l N -r 80 -png`로 이미지로 보고 인쇄된 쪽 번호가 「책 M쪽」과 같은지 본다. 다르면 덱목록 `pdfOffset`이 틀린 것이다 — 이 덱에서는 맞는 값으로 읽고, 보고에 「offset 다름: 덱목록 〔a〕 → 실제 〔b〕」를 적는다(덱목록은 관리자가 고침). 머리줄의 「책 M쪽」 자체가 틀린 PDF도 있다(표지·차례가 앞에 붙은 경우).
3. 덱이 다루는 쪽만 읽는다. 식·수치·기호·화학식·그래프 값·표는 추출 텍스트가 깨지기 쉬우므로 **쪽 이미지로 확인**하고 옮긴다.
4. 교과서 활동 이름·문항 번호·예제 번호는 교과서 그대로 쓴다. 교과서에서 확인하지 못한 문항 번호를 지어내지 말고, 덱이 만든 문항은 `확인 문제 01`(tag q)로.

## 2. 지도서 대조 단계
- 지도서 PDF가 있으면 [구성안]에서 덱 범위의 「교과서 N 쪽」을 Grep으로 찾아 지도 내용(지도 방안·유의점·오개념·예시 답안·채점 기준·탐구 결과 예시)을 반영한다. 쪽 색인 파일이 있으면(`SRC/_추출/<과목 키>_지도서_쪽색인.txt`) 그것으로 찾는다.
- **이미 만든 덱에 지도서가 나중에 왔을 때 [지도서 대조]**: 덱을 새로 만들지 않고 틀린 것만 고친다.
  1. plan.md 「확인이 필요한 점」을 먼저 읽는다.
  2. 대조: 정답(확인 문제·마무리), 서술형 예시 답안·채점 요소, 탐구 결과 예시값·결과 정리 예시, 해 보기 예시, 지도 유의점의 오개념.
  3. 덱 값이 지도서와 다르면 지도서 값으로(단, 지도서가 틀렸으면 3절 「교과서·지도서 오류」대로). 실험실 예시값이 지도서와 크게 다르면 맞춘다.
  4. 덱이 「지도서 없음」이라 적어 둔 표시를 지운다.
  5. 지도서의 좋은 보충(오개념 지도)은 짧게 반영해도 되지만 장을 크게 늘리지 않는다.
  6. plan.md 끝에 「지도서 대조 반영 기록」, 「확인이 필요한 점」에서 해결된 항목 정리.
- **지도서가 없을 때**: 정답은 직접 풀어 검산하고, 예시 답안·탐구 결과 예시·서술형 채점 요소는 덱이 만들어 plan.md 「확인이 필요한 점」에 「지도서 없음 — 직접 만든 예시: 〔장 번호·내용〕」으로 하나하나 적는다. 선생님에게 묻느라 멈추지 않는다.

## 3. 교과서·지도서 오류를 발견했을 때
덱에는 **바른 값**을 쓰고, 그 장에 교과서 값을 작게 함께 적는다: `<span class="small c-muted">(교과서 ○○쪽에는 「…」로 되어 있음)</span>`. plan.md 「확인이 필요한 점」에 근거(다시 푼 계산, 자료 출처)를 적고 보고 「확인 필요」에 올린다. 반올림·표기 차이처럼 판단이 갈리는 것은 교과서 값을 따르고 확인 필요에만 적는다.

## 4. 이 환경의 사정 〔관리자가 채움〕
1. 〔있는 자료: 교과서 PDF 〔과목·권〕, 지도서 〔있음/없음〕, 교육과정 문서 〔 〕〕
2. 헤드리스 Chrome: 〔기본 경로 / `export CHROME=…`〕. 렌더 결과 첫 줄이 「KaTeX 로드됨」이어야 한다(CDN이 막힌 환경이면 로컬 KaTeX 서버를 먼저 띄우는 명령을 여기에 적는다).
3. Python 실행: 〔`python` / `python3 -I`〕
4. 본보기(품질 기준): 〔같은 과목에서 먼저 완성한 덱 / `SRC/content/과학공통_본보기/0-0-1_과학_공통_본보기/`〕
5. 같은 대단원에 먼저 만든 덱이 있으면 그 plan.md 0절 「덱 공통 약속」과 slides.html 구성을 먼저 읽고 맞춘다. 대단원 첫 소단원 덱은 `withUnitIntro`대로 도입을 앞머리에.
6. 단원 마무리 덱(`…-M`)은 과학공통 약속 9절대로 같은 대단원 소단원 덱들의 plan.md·slides.html을 읽고 만든다.

## 5. 생성 스크립트 — OUT 경로 assert
그림 좌표·반복 장을 Python 생성 스크립트(WORK/gen.py)로 만들 때:
- 스크립트 맨 위에 출력 경로를 상수로 두고 **assert로 확인**한다. 다른 덱 폴더를 덮어쓴 사고를 막는다.
  ```python
  OUT = r"〔ROOT〕/차시자료/_소스/content/<과목 키>/<folder>/slides.html"
  assert "/content/<과목 키>/<folder>/" in OUT.replace("\\", "/"), OUT
  ```
- 스크립트로 만든 뒤 slides.html을 직접 고쳤으면, 스크립트를 다시 돌리기 전에 그 고침이 덮이지 않는지 확인한다(덮이면 slides.html을 직접 고치거나 스크립트에 반영). plan.md 0절에 「slides.html이 원본 — gen.py 다시 돌리지 말 것」 또는 「gen.py가 원본」을 적는다.
- 끝나면 스크립트를 `SRC/작업지시/덱_생성스크립트/<과목 키>_<id>/`에 남긴다(관리 도구 `tools/관리/gdone.sh`에 `WORK=`를 주면 복사).

## 6. 점검 — PRE 시험, render·motion·ask, sheet 두 번
- **PRE 시험(실험실)**: `PRE="$(cat WORK/lab.js)" node _labtest.mjs "../../<과목 키>/<folder>.html" "WORK/labtest" --slides=N`. 슬라이더에 값을 넣고 `input` 이벤트, 버튼 `click`, 그 뒤 output 글자·기록 표 행 수를 `console.warn('LAB …')`로 찍어 **조작마다 결과가 바뀌는지, 표가 쌓이는지, 초기화되는지** 확인한다. `_labtest.mjs`의 '콘솔 오류' 수에는 이 warn 줄이 들어가므로 덱 점검은 render.mjs 결과로 판단한다. PRE가 async(Promise)를 기다려야 하면 setTimeout 대신 동기 조작으로 쓰거나, 사본을 WORK에 만들어 기다리게 한다(tools 원본은 고치지 않음).
- **끝 조건**: `render.mjs` 자동 점검 0건·콘솔 오류 0건 · `motion_check.mjs` 0 · `ask_check.mjs` 0 · 전체 캡처를 **sheet.py 모음으로 두 번**(완성 직후 한 번, 검토+수정 뒤 최종 한 번) 빠짐없이 본다 · 검토 파일 두 개(`검토/<과목 키>_<id>_content.json`, `_visual.json`) · plan.md 끝 반영 기록.

## 7. 화면에 출판사 이름을 쓰지 않는다
표지 meta 줄은 「고등학교 통합과학1 12–17쪽」·「중학교 과학2 34–41쪽」, meta.json header는 「(고등 통합과학1 12–17쪽)」. 「(〔출판사〕)」, 「, 〔출판사〕」를 넣지 않는다. 폴더·과목 키(`통합과학1_〔출판사〕`)는 그대로 둔다. 교과서 쪽 사진·출판사 로고·교과서 고유 캐릭터도 넣지 않는다.

## 8. 덱 하나씩, 사용량 제한 시 이어 하기
- **한 번에 한 덱**만 맡는다. 다른 덱을 함께 만들지 않는다(같은 대단원 덱은 앞 덱의 0절 약속을 이어받아야 하므로 순서대로).
- 사용량 한도로 멈출 수 있다. 그래서 **단계가 끝날 때마다 파일에 남긴다**: plan.md(구성안 완료 표시), slides.html(쓴 장까지), 검토 json. 다시 시작하면 plan.md·slides.html·검토 파일을 먼저 읽고 **빠진 곳부터 이어서** 한다(처음부터 다시 쓰지 않는다).
- 관리자는 `SRC/작업지시/진행상황.md`에 덱마다 상태(⬜ 대기 · 🔄 작업 중 · ✅ 완료)를 적는다(`tools/관리/prog.py`). 이어 할 때는 🔄인 덱부터.

## 9. 꼭 지킬 것
- **고치지 않는 것**: `SRC/engine/*`, `SRC/tools/*`, `SRC/vendor/*`, 사이트 파일(`ROOT/차시자료/index.html`, `view.html`, `edit.html`, `js/`, `css/`), `decks.json`, 다른 덱 폴더와 결과 HTML(본보기 포함 — `build.py`는 반드시 `<과목 키>/<id>`를 붙여 그 덱만 빌드), `SRC/작업지시/진행상황.md`. **git commit·push·firebase deploy·site_index.py는 하지 않는다**(관리자가 함).
- 고치는 것: `SRC/content/<과목 키>/<folder>/`의 파일, `SRC/작업지시/검토/<과목 키>_<id>_*.json`, 빌드 결과(build.py로만), WORK 안의 임시 파일.
- 필수 탐구(`requiredInquiry`)는 **실험실 + 탐구 장**으로 반드시 이행하고 PRE 시험으로 확인.
- 범위 제한(과목 약속 2절)과 표기(`\ce{}`, 단위, 유전자 기호), 검산 절을 지킨다.
- 사용량을 아낀다(공통.md 4절).
