# 차시 덱 작업 지시서 (에이전트 공통 — 과학 공통: 통합과학1·2, 중학교 과학1·2·3, 확장 과목)

이 문서는 2022 개정 교육과정 과학 수업용 슬라이드 덱을 만들고 다듬는 에이전트가 따르는 공통 지시서다. 덱마다 맡는 일(구성안, 제작, 움직임, 검토, 수정)은 에이전트를 부를 때 따로 알려 준다.

경로 약속: `ROOT` = 이 묶음을 푼 폴더(`docs`와 `차시자료`가 있는 곳), `SRC` = `ROOT/차시자료/_소스`, `WORK` = 이 덱의 임시 작업 폴더(scratch 안 `<과목 키>_<id>/`, 없으면 `SRC/_render/_작업/<과목 키>_<id>/`)

## 0. 덱 정보 찾기

- 과목 키 = `<과목>_<출판사>`: 예 `통합과학1_출판사`, `통합과학2_출판사`, `과학1_출판사`, `과학2_출판사`, `과학3_출판사`(실제로는 출판사 이름을 넣는다. 확장: `물리학_출판사`, `생명과학_출판사`, `지구과학_출판사`). 폴더·키에는 출판사 이름을 써도 되지만 **화면에는 쓰지 않는다**(과학공통 약속 1절).
- 덱 목록: `SRC/작업지시/덱목록.json` → `[과목 키].units[대단원]`(교과서·지도서 파일, 쪽 대응 `pdfOffset`·`guideOffset`, 주의 사항)과 `[과목 키].decks[]`(id, unit, folder, title, header, bookPages, standard, idPrefix, withUnitIntro, review, requiredInquiry, labCandidate, area, split, note). 필드 뜻은 덱목록.json `_필드`.
- 과목 약속: `SRC/작업지시/과학공통_약속.md`(모든 과목 공통) + `SRC/작업지시/<과목>_약속.md`(틀: `통합과학_약속_틀.md`, `중학과학_약속_틀.md`를 복사해 채운 것).
- 영역 팩: `ROOT/docs/슬라이드_제작_가이드라인_과학공통.md` 10장 — 덱목록 `area`(물리·화학·생명·지구·융합)의 팩을 읽는다.
- 성취기준 원문: `ROOT/docs/교육과정_<과목>_성취기준.md`(선생님이 준 교육과정 문서로 만든 것). 없으면 만들고, 문서가 없으면 선생님에게 받는다 — **코드·문장을 지어내지 않는다**.
- 내용 폴더: `SRC/content/<과목 키>/<folder>/` — `plan.md`, `meta.json`, `slides.html`, `labs.js`, `extra.css`, `img/`
- `meta.json`: `{"title": "<title>", "file": "<folder>", "header": "<header>"}` — 값은 덱목록.json 그대로
- 결과 파일: `ROOT/차시자료/<과목 키>/<folder>.html` · 캡처: `SRC/_render/<과목 키>/<folder>/`
- 같은 대단원의 다른 덱이 이미 있으면 그 `plan.md` 0절 "덱 공통 약속"과 `slides.html`을 읽고 용어·기호·색·크기·개념 지도를 맞춘다.

## 1. 작업 환경

- 엔진 구현: `SRC/AUTHORING.md`
- 교과서·지도서 PDF는 `SRC/_자료/`에 덱목록.json의 파일 이름으로. 쪽별 텍스트: `cd "SRC/tools" && python extract_pages.py "../_자료/<파일>.pdf" "../_추출/<파일>.txt" --offset=<pdfOffset>`(이미 있으면 다시 만들지 않는다). 머리줄 `=== p.<PDF쪽> (책 <쪽>쪽) ===`을 Grep으로 찾아 offset/limit로 읽는다. **offset은 반드시 확인**한다: PDF 몇 쪽을 이미지로 보고 인쇄된 쪽 번호와 맞는지(에이전트_안내 1절).
- 빌드: `cd "SRC/tools" && python build.py <과목 키>/<folder>` — 반드시 과목 키를 붙여 그 덱만.
- 점검·캡처: `node render.mjs "../../<과목 키>/<folder>.html" "../_render/<과목 키>/<folder>"`(일부만 `--slides=3,5-8`). 단계별 `--steps`는 하위 폴더 `…/<folder>/steps`로(render.mjs는 시작할 때 출력 폴더의 s*.png를 지운다). Chrome이 기본 경로에 없으면 환경 변수 `CHROME`.
- **캡처 모음**: `python sheet.py "../_render/<과목 키>/<folder>"`(일부 `--slides=3-10`, 단계별 `--steps`) → 4장을 한 장에(`sheet_NN_MM.png`). 훑어보기는 이것으로, 자세히 볼 장만 `sNN.png`.
- 움직임·질문 강조: `node motion_check.mjs <과목 키>/<folder>`, `node ask_check.mjs <과목 키>/<folder>`.
- 실험실 시험: `PRE="$(cat WORK/lab.js)" node _labtest.mjs "../../<과목 키>/<folder>.html" "WORK/labtest" --slides=N` — PRE의 `console.warn('LAB …')`가 `[warning] LAB …`으로 나온다(이 줄은 콘솔 오류 수에 들어가므로 덱 점검은 render.mjs로 판단).
- 캡처 PNG와 PDF 쪽은 이미지로 본다. PDF가 안 열리면 `pdftoppm -f N -l N -r 80 -png` 또는 PyMuPDF.
- **추출 텍스트의 기호 깨짐**: 첨자 분리(`H O` + `2`), × → `_`, ℃ → `¾`, Δ → `D`, 그리스 문자, 표·그래프 값. **식·수치·화학식·기호는 반드시 PDF 쪽 이미지로 확인**한다.
- 임시 파일(생성 스크립트, 시험 스크립트)은 `WORK` 안에만.
- 고치지 않는 것: `SRC/engine/*`, `SRC/tools/*`, `SRC/vendor/*`, 사이트 파일, 다른 덱 폴더. 엔진·도구 문제는 고치지 말고 보고한다.
- 교과서 그림·사진은 복사하지 않고 직접 그린 SVG로. 교과서 문장을 길게 베끼지 않는다.

## 2. 먼저 읽을 것 (구성안·제작 단계)

- `ROOT/docs/슬라이드_제작_가이드라인_과학공통.md` — 2장(공통 규칙), 3장, 5장, 6.4, 6.5, 7장, 8장, **10장의 해당 영역 팩**(덱목록 `area`)
- `SRC/AUTHORING.md` (전부)
- `SRC/작업지시/과학공통_약속.md` (전부) + `SRC/작업지시/<과목>_약속.md`
- 본보기: `SRC/content/과학공통_본보기/0-0-1_과학_공통_본보기/`(slides.html 필요한 장만 Grep, labs.js). 같은 과목·대단원에 먼저 만든 덱이 있으면 그것이 우선이다.
- [구성안]·[검토-내용]: 교과서(·지도서) 추출 텍스트에서 **이 덱이 다루는 쪽만** 읽는다. 지도서는 "교과서 N 쪽" 표시를 Grep으로 찾는다. [제작]은 교과서를 다시 읽지 않는다 — plan.md에 화면 문장이 다 있다.

## 3. 할 일별 절차

### [구성안]
`plan.md`를 작성한다. 이미 있으면 빠진 절만 이어서 완성한다(처음부터 다시 쓰지 말 것).
- 맨 앞(0절): 덱 정보(폴더, meta.json, 범위 쪽, 쪽 대응, 성취기준 코드와 문장, 영역, 총 장수와 구성) + 덱 공통 약속 표(data-sec 꼴, 개념 번호, 표식, 용어·기호·단위, 상수 값, 색, 크기(원자 반지름·힘 축척), id 접두어, 개념 지도 이어가기)
- 각 장: 번호, 템플릿, data-sec, data-title, h2 제목·표식, **화면에 들어갈 실제 문장·식(LaTeX)·화학식(`\ce{}`)·문항·정답 전문**, 단계 공개, 그림(배치·라벨·색·수치), 실험실 명세(입력·계산식·표시값·기록 표·그래프), 근거 쪽(교과서·지도서)
- **필수 탐구(S12)**: 덱목록의 `requiredInquiry`를 먼저 확인하고, 탐구마다 **탐구 이행 절**(성취기준 탐구 활동 원문, 교과서 활동(쪽)과 겹치는/빠진 부분, 실험실 명세, 탐구 장 묶음(S7 + 안전 S9), 동사별 대응표). 실험실과 탐구 장 둘 다 필수.
- 교과서의 모든 내용·활동·예제·문항을 빠짐없이, 지도서의 지도 내용(지도 방안, 유의점, 오개념, 예시 답안, 평가 기준)을 발문·단계 공개·정답에 반영한다.
- **검산 절**: 모든 계산 문항을 다시 풀어 적고(교과서·지도서 정답과 다르면 그 사실과 근거), 반응식은 원자 수·전하, 그래프는 계산식과 점 값, 유전 문항은 교배표, 지사 문항은 법칙별 근거를 적는다(과학공통 약속 11절 꼴).
- **범위 점검 절**: 교육과정 성취기준 해설·적용 시 고려 사항, 지도서 「지도상의 유의점」에 걸리는 내용이 없는지 한 줄씩. 다른 학년·과목에서 배울 내용(선행)을 넣지 않는다.
- 마지막 절: **확인이 필요한 점**(교과서·지도서로 확인 못 한 값, 덱이 만든 예시 답안, 교과서 오류 의심).

### [제작]
`plan.md`대로 `meta.json`, `slides.html`, `labs.js`, 필요하면 `extra.css`·`img/`를 쓰고 빌드한다. 이미 `slides.html`이 있으면 이어서 완성한다.
- 필수 탐구 실험실은 조작마다 결과가 실제로 달라지고 측정 표·그래프가 쌓이는지 PRE 시험으로 확인한다.
- 식은 `$…$`, 화학식은 `\ce{}`, 그림 속 글자는 `text.tex`. 그래프는 계산값으로(생성 스크립트 또는 labs.js).
- render.mjs로 **자동 점검 0건(C1 포함)·콘솔 오류 0건**까지 고친다.
- 몇 장 쓸 때마다 `--slides=`로 그 장만 캡처해 확인. 다 쓴 뒤 전체를 sheet.py 모음으로 빠짐없이 본다(전체 보기 2회: 완성 직후·최종). 그림·실험실이 복잡한 장은 원본 sNN.png로.
- 단계가 겹치는 장은 `--steps`로 공개 순서 확인.
- **움직임(가이드라인 6.4)**: `data-anim`으로 이해를 돕는 움직임(그린 모습 = 마지막 모습, 과학적으로 맞게, 덱마다 15–25곳). `motion_check.mjs` 0건.
- **질문 먼저(6.5)**: 답 단계 앞 질문에 '?' 또는 'Q'. `ask_check.mjs` 0건.

### 웹 수정본이 있는 덱
웹사이트에서 관리자가 고친 덱은 웹 수정본이 원본을 가린다. 이미 배포된 덱을 다시 빌드하기 전에 선생님에게 웹 수정본이 있는지 묻고, 있으면 「수정본 내려받기」 파일을 받아 그 변경을 `slides.html`에 합친 뒤 빌드한다. 보고에 "웹 수정본 합침: 있음/없음".

### [움직임] (이미 있는 덱에 그림 움직임 넣기)
원본 `slides.html`의 정적 SVG에 `data-anim`을 넣는다(실험실·엔진은 그대로). 빌드 → render 0·콘솔 0 → motion_check 0 → ask_check 0 → 몇 장은 `?motion` 중간 프레임을 남긴다. 움직이는 물체에 붙은 화살표·라벨은 같은 묶음에(M-D, `force_check.mjs`로 후보 확인).

### [검토-내용] (파일을 고치지 않는다)
과학 교사·교과서 검토자·국어 교정자로서 본다. 화면 디자인은 보지 않는다.
- 교과서(·지도서) 해당 쪽과 대조: 모든 개념·정의·탐구·활동·예제·확인·문항이 빠짐없이 정확한가(빠지면 high).
- **필수 탐구(S12)** 이행과 탐구 문장의 모든 동사(빠지거나 일부만이면 high).
- 모든 수치·단위·유효 숫자·계산·정답·해설을 다시 풀어 검증하고, 반응식(원자 수·전하)·교배 비·지사 순서·그래프 값을 검산한다. `labs.js` 계산식도 코드로 확인한다.
- 용어·기호가 교과서 표기와 같은가(띄어쓰기 포함).
- 그림의 과학(힘 방향·길이 비례, 작용 반작용 쌍, 회로 극·전류 방향, 원자 수 보존, 세포 구조 이름, 가계도 기호, 지층 순서·무늬, 판 이동 방향, 궤도 방향, 축 라벨, 색 뜻 D7)을 캡처로 확인한다.
- 오개념 유발 표현(영역 팩의 오개념 목록), 교육과정 범위 초과.
- 수업 흐름: 질문 → 생각 → 답(S1), 현상 → 모형 → 기호(S10), 한 장에 한 문항(S2), 단계 카드(S3), 연결(S5), 안전(S9), 중학교 수준(S14).
- 한국어: 맞춤법·띄어쓰기·번역투·긴 문장·용어 일관성.

### [검토-화면] (파일을 고치지 않는다)
디자인 검수자로서 본다. 과학 내용 판단은 하지 않는다.
- 모든 sNN.png를 원본으로 한 번(한 메시지에 6–8장씩). 단계가 겹치는 장은 `--steps` 모음.
- 겹침·잘림·넘침·끊긴 도선·비대칭이면 안 되는 그림·지나친 빈 공간/쏠림·빽빽함·19px 미만 본문·화면 18px 미만 그림 라벨·정답 가운데.
- T1–T6, M1–M9, C1, D1–D11과 영역 팩 그림 규칙을 slides.html 코드와 캡처 양쪽에서(유니코드 첨자, 본문 글자 화학식, 가운뎃점, 단위 위치, 축 라벨, id 고유, 색 뜻, 무늬·범례).
- 본보기보다 수준이 떨어지는 장(그림 빈약, 글만 많음).

검토 결과는 `SRC/작업지시/검토/<과목 키>_<id>_content.json` 또는 `_visual.json`에:
`{"findings":[{"slide":3,"severity":"high|medium|low","rule":"D12","problem":"…","fix":"…"}],"summary":"…"}`

### [수정]
지적을 하나씩 교과서·지도서·AUTHORING.md·캡처로 직접 확인하고 맞는 것만 반영한다(틀린 지적은 이유와 함께 기각). high·medium은 모두 판단해 처리, low도 쉬우면 반영.
- 고치는 동안 `--slides=`로 바꾼 장만 확인. 다 고친 뒤: 빌드 → render(전체) 0·0 → **전체 캡처 모음 최종 확인** → 예제·실험실·단계 카드 몇 장 `--steps`.
- `plan.md` 끝에 반영 기록(반영/기각과 이유).

### [검토+수정]
따로 검토 파일이 없을 때. [검토-내용]·[검토-화면]으로 스스로 엄격하게 검토해 두 json을 저장한 뒤 [수정]을 따른다. 덱을 처음 보는 사람의 눈으로 본다.

### [지도서 대조]
에이전트_안내 「지도서 대조」 절을 따른다(이미 만든 덱을 지도서와 대조해 틀린 것만 고침).

## 4. 사용량 아끼기 (꼭 지킨다)

- 서로 독립인 도구 호출은 한 메시지에 동시에. 캡처는 한 메시지에 6–8장씩.
- 훑어보기는 sheet.py 모음으로. 원본 sNN.png는 자세히 볼 장만.
- 큰 파일(plan.md·slides.html·교과서·지도서 텍스트)은 한 번만 읽고, 다시 볼 때는 Grep + offset/limit.
- 수정 중에는 `--slides=`로 바꾼 장만, 전체 캡처는 마지막에 한 번.
- 편집은 모아서. 반복되는 기계적 수정은 짧은 Python 스크립트 한 번으로.
- PDF 쪽 이미지는 그림·식·수치 확인이 꼭 필요할 때만(추출 텍스트가 깨졌으면 꼭).
- plan.md의 그림 명세는 좌표·라벨·색·수치 위주로 간결하게(코드를 길게 붙여 넣지 않는다).
