# 덱 작업 지시서 (에이전트 공통 — 범용)

이 문서는 어떤 주제(교사 연수, 교과 수업, 학부모 설명회, 발표 …)의 슬라이드 덱이든 만들고 다듬는 에이전트가 따르는 공통 지시서다. 덱마다 맡는 일(구성안, 제작, 움직임, 검토, 수정)은 부를 때 따로 알려 준다.

경로 약속: `ROOT` = 이 묶음을 푼 폴더(`docs`와 `차시자료`가 있는 곳), `SRC` = `ROOT/차시자료/_소스`

## 0. 덱 정보 찾기

- **덱 정보 네 가지 — 주제·대상·시간·목표.** 덱목록에 있으면 거기서 읽고, 없으면 선생님에게 이 네 가지를 먼저 묻는다(한 번에 짧게). 대상이 정해지면 약속 파일이 정해진다.

  | 대상 | 약속 파일 (`SRC/작업지시/약속_예시/`) |
  |---|---|
  | 교사 연수·워크숍 | `교사연수_약속.md` |
  | 교과 수업(학생) | `교과수업_약속.md` |
  | 학부모 설명회 | `학부모설명회_약속.md` |
  | 일반 발표(학회, 보고, 공모) | `발표_약속.md` |

- 덱 목록: `SRC/작업지시/덱목록.json` → `[묶음 키]`(label, audience, promise, minutesPerSession, units)와 `[묶음 키].decks[]`(id, unit, folder, title, header, idPrefix, minutes, slides, goals, structure, materials, checkFacts, note). 필드 뜻은 파일 맨 앞 `_필드`.
- 덱목록에 없는 새 덱이면 [구성안]에 들어가기 전에 그 꼴로 항목을 하나 추가해 선생님에게 보인다(묶음 키·폴더 이름은 한국어 가능, 띄어쓰기는 `_`).
- 내용 폴더: `SRC/content/<묶음 키>/<folder>/` — `plan.md`, `meta.json`, `slides.html`, `labs.js`, `extra.css`, `img/`, `자료/`
- `meta.json`: `{"title": "<title>", "file": "<folder>", "header": "<header>"}` — 값은 덱목록 그대로. 꼬리말은 `SRC/묶음설정.json`의 `credit`이 모든 덱 표지에 들어간다(덱만 바꾸려면 meta.json에 `"credit"`).
- 결과: 빌드본 `ROOT/차시자료/<묶음 키>/<folder>.html`, **완성본(선생님이 받는 파일)** `ROOT/차시자료/완성본/<묶음 키>/<folder>.html` · 캡처 `SRC/_render/<묶음 키>/<folder>/`
- 같은 묶음의 다른 덱이 이미 있으면 그 `plan.md` 앞부분의 "덱 공통 약속"과 `slides.html`을 읽고 용어·색·표식·꼴을 맞춘다. 먼저 완성된 덱이 본보기다.

## 1. 작업 환경

- 엔진 쓰는 법: `SRC/AUTHORING.md`
- **자료(선택)**: 선생님이 준 PDF·문서(연수 원고, 지침, 교과서, 매뉴얼)는 `SRC/content/<묶음 키>/<folder>/자료/`에 복사해 둔다(원본은 그대로). PDF는 `cd "SRC/tools" && python extract_pages.py "<pdf>" "<같은 폴더>/<이름>_추출.txt"`(쪽 번호를 맞추려면 `--offset=N`: 책 쪽 = PDF 쪽 + N)로 쪽별 텍스트를 만들고, 머리줄 `=== p.N ===`을 Grep으로 찾아 필요한 쪽만 읽는다. 표·숫자·기호가 깨질 수 있으니 중요한 값은 PDF 쪽 이미지로 확인한다(PyMuPDF 또는 `pdftoppm -f N -l N -r 80 -png`).
- 빌드: `cd "SRC/tools" && python build.py <묶음 키>/<folder>`
- 점검·캡처: `node render.mjs "../../<묶음 키>/<folder>.html" "../_render/<묶음 키>/<folder>"` (일부만 `--slides=3,5-8`)
  - 단계별 캡처(`--steps`)는 하위 폴더로: `"../_render/<묶음 키>/<folder>/steps"`
  - Chrome이 기본 경로(Windows Chrome·Edge, macOS Chrome, Linux google-chrome·chromium)에 없으면 환경 변수 `CHROME`에 실행 파일 경로.
- **캡처 모음**: `python sheet.py "../_render/<묶음 키>/<folder>"`(일부 `--slides=3-10`, 단계별 `--steps`) → 4장을 한 장에 모은 `sheet_NN_MM.png`. 전체 훑어보기는 이것으로(사용량 1/4), 자세히 볼 장만 원본 `sNN.png`. Pillow 필요.
- 움직임·질문 강조 점검: `node motion_check.mjs <묶음 키>/<folder>`, `node ask_check.mjs <묶음 키>/<folder>`
- **완성본**: `python build.py <묶음 키>/<folder> --offline` → `node verify_offline.mjs "../../완성본/<묶음 키>/<folder>.html"` (OK = 외부 요청 0, KaTeX 오류 0, 점검 0). 본문 글꼴을 받는 동안만 인터넷이 필요하다.
- 실험실 동작 확인용 임시 스크립트는 scratchpad의 **덱 이름 하위 폴더**에 둔다.
- 고치지 않는 것: `engine/*`, `tools/*`, `vendor/*`, 다른 덱 폴더. 엔진·도구 문제는 고치지 말고 보고한다.
- 그림은 직접 그린 SVG 또는 선생님이 준 그림(`img/`). 남의 그림·사진을 복사하지 않고 자료 문장을 길게 베끼지 않는다.

## 2. 먼저 읽을 것 (구성안·제작 단계)

- `ROOT/docs/슬라이드_제작_가이드라인_범용.md` (전부 — 특히 2장 규칙, 2.6 흐름 S1–S15, 3.3 템플릿, 6.4·6.5)
- `SRC/AUTHORING.md` (전부)
- 대상 약속 파일 `SRC/작업지시/약속_예시/<대상>_약속.md` (전부)
- 덱목록의 이 덱 항목과, 선생님이 준 자료(이 덱이 쓰는 쪽만)
- 같은 묶음에서 먼저 만든 덱이 있으면 그 `plan.md` 0절과 `slides.html` 앞 300줄
- [제작]은 자료를 다시 읽지 않는다 — plan.md에 화면 문장이 다 있다(그림 모양을 확인할 쪽만 본다).

## 3. 할 일별 절차

### [구성안]
`plan.md`를 쓴다. 이미 있으면 먼저 읽고 빠진 절만 이어서 끝까지 완성한다(처음부터 다시 쓰지 말 것).
- **0절 덱 정보**: 주제·대상·시간·목표(덱목록 `goals`), 폴더, meta.json, 총 장수와 구성(약속 파일의 세션 구성에 시간 배분), 자료 목록(파일·쪽).
- **0절 덱 공통 약속 표**: data-sec 꼴, 번호, 표식, 용어 표기, 기준 값(M11), 색 뜻(D7), id 접두어, 실습 시간.
- **각 슬라이드**: 번호, 템플릿(가이드라인 3.3), data-sec, data-title, h2 제목·표식, **화면에 들어갈 실제 문장·질문·답 전문**, 단계 공개(.step / data-g), 그림(배치·라벨·색), 실험실 명세(입력·계산·표시·움직임), 근거(자료 쪽 또는 출처), 발표자 메모(말로 할 것 — 화면에는 넣지 않음, 한두 줄).
- **목표 이행 절(S12)**: 덱목록 `goals` 하나하나가 어느 장·활동에서 이루어지는지 표. 교과 수업이면 성취기준·필수 활동 대응표(교과수업 약속).
- **출처 절(S15)**: 화면에 나오는 사실(법령·지침·기준 이름, 숫자, 날짜, 기관, 사례)마다 출처(선생님 자료 쪽, 공식 문서 이름). 출처가 없으면 "확인이 필요한 점"으로.
- **시간 점검 절**: 장별 예상 시간의 합이 덱 시간(덱목록 `minutes`) 안인지, 실습·질의 시간이 약속 파일 비율을 지키는지.
- 마지막 절: **확인이 필요한 점** — 선생님만 알 수 있는 것(학교 사정, 실제 연락처·장소, 활동지 유무, 지어내면 안 되는 사실).
- 끝나면 선생님에게 "확인이 필요한 점"만 짧게 묻는다.

### [제작]
`plan.md`대로 `meta.json`, `slides.html`, 필요하면 `labs.js`(실험실·타이머), `extra.css`, `img/`를 쓰고 빌드한다. `slides.html`이 이미 있으면 이어서 완성한다(plan.md가 없거나 미완성이면 [구성안]부터).
- render.mjs로 **자동 점검 0건·콘솔 오류 0건**까지 고친다.
- 몇 장씩 쓸 때마다 `--slides=`로 그 장만 캡처해 원본으로 확인한다. 다 쓴 뒤 전체를 캡처 모음(sheet.py)으로 빠짐없이 본다(전체 보기 2회: 완성 직후·최종). 겹침·잘림·어색한 배치·빈 공간·쏠림을 고친다.
- 단계가 겹치는 장은 `--steps`(하위 폴더)로 공개 순서를 확인한다.
- **움직임(가이드라인 6.4)**: 이해를 돕는 `data-anim`을 넣는다(그린 모습 = 마지막 모습, 덱마다 8–20곳). `node motion_check.mjs <묶음 키>/<folder>` 문제 0.
- **질문 강조(6.5)**: 답 단계 앞 질문에 '?' 또는 'Q'. `node ask_check.mjs <묶음 키>/<folder>` 0건.
- 실험실·타이머는 임시 스크립트로 단추를 눌러 값이 바뀌는지 확인한다.
- 마지막에 **완성본**을 만들고 `verify_offline.mjs` OK를 확인한다.

### [움직임] (이미 있는 덱에 그림 움직임 넣기)
원본 `slides.html`의 정적 SVG에 `data-anim`을 넣는다(실험실·엔진은 그대로). 글이 많은 장은 내용을 바꾸지 않고 설명을 한두 단계로 나누는 정도만(결론·답은 끝에). 빌드 → render.mjs 0·0 → motion_check 0 → ask_check 0 → 몇 장은 `?motion` 중간 프레임 캡처(`_render/동작_후/<묶음 키>/<folder>/frames/`).

### [검토-내용] (파일을 고치지 않는다)
그 분야 전문가·청중 대표·국어 교정자로서 본다. 화면 디자인은 보지 않는다.
- 선생님 자료와 대조: 목표(S12)가 빠짐없이 이행되었는가(빠지면 high), 자료의 핵심이 바르게 옮겨졌는가.
- **사실 확인(S15)**: 화면의 모든 법령·지침·기준 이름, 숫자, 날짜, 기관, 사례를 출처와 하나씩 대조한다. 출처가 없거나 다르면 high.
- 대상에 맞는가: 말투(연수: 동료 교사에게 / 설명회: 쉬운 말), 용어 설명, 분량, 시간 배분(약속 파일).
- 흐름: 질문 → 생각 → 답(S1), 왜 → 무엇 → 어떻게(S5), 사례 → 그림 → 정리(S10), 한 장에 한 과제(S2), 단계 카드(S3), 실습 안내(S13), 정리(S14), 안전(S9 — 실습이 있으면).
- 오해를 부르는 표현, 지나친 일반화, 개인 정보(학생 이름·사진·연락처).
- 한국어: 맞춤법·띄어쓰기·번역투·긴 문장·용어 일관성.

### [검토-화면] (파일을 고치지 않는다)
디자인 검수자로서 본다. 내용 판단은 하지 않는다.
- 캡처 폴더의 모든 sNN.png를 원본으로 한 번 본다(한 메시지에 6–8장씩 동시에 Read). 단계가 겹치는 장은 `--steps` + `sheet.py --steps`.
- 겹침·잘림·넘침, 대칭이어야 할 것(같은 카드 크기·간격), 지나친 빈 공간/쏠림·빽빽함, 19px 미만 본문, 화면 18px 미만 그림 라벨, 정답 가운데 정렬, 색 뜻(D7)·색만으로 뜻 전달 금지, 표지 꼬리말 위치.
- T1–T5, M1–M6·M9(수식이 있으면), D2–D11을 slides.html 코드와 캡처 양쪽에서.
- 글만 많은 장(그림·구조가 빈약)을 찾는다.

검토 결과는 `SRC/작업지시/검토/<묶음 키>_<id>_content.json` 또는 `<묶음 키>_<id>_visual.json`에:
`{"findings":[{"slide":3,"severity":"high|medium|low","rule":"S15","problem":"…","fix":"…"}],"summary":"…"}`

### [수정]
검토 파일의 지적을 하나씩 자료·AUTHORING.md·캡처로 직접 확인하고 맞는 것만 반영한다(틀린 지적은 이유와 함께 기각). high·medium은 모두 판단해 처리하고, low도 쉬우면 반영한다.
- 고치는 동안에는 `--slides=`로 바꾼 장만 캡처해 본다. 다 고친 뒤: 빌드 → render.mjs(전체) → 0건·0건 → **전체를 캡처 모음으로 최종 확인** → 몇 장은 `--steps` → 완성본 다시 만들기 → verify_offline OK.
- `plan.md` 끝에 반영 기록(반영/기각과 이유)을 덧붙인다.

### [검토+수정]
검토 파일이 없거나 한쪽 관점만 있을 때. 빠진 관점으로 스스로 꼼꼼히 검토해 `SRC/작업지시/검토/<묶음 키>_<id>_<관점>.json`에 저장한 뒤 [수정] 절차를 따른다. 덱을 처음 보는 사람의 눈으로 엄격하게 본다.

### 선생님이 고친 파일을 받았을 때
선생님이 완성본을 다른 프로그램으로 고쳐 돌려주면, 그 변경(글자)을 `slides.html`에 옮겨 적고 다시 빌드한다. 빌드본·완성본 HTML을 직접 고치지 않는다(다음 빌드 때 사라진다).

## 4. 사용량 아끼기

- 독립인 도구 호출은 **한 메시지에 동시에**. 캡처 PNG는 6–8장씩 동시에 Read.
- 전체 훑어보기는 캡처 모음(sheet.py), 원본은 자세히 볼 장만.
- 큰 파일(plan.md, slides.html, 자료 추출 텍스트)은 한 번만 읽고, 다시 볼 때는 Grep + offset/limit.
- 수정 중에는 `--slides=`만, 전체 캡처는 마지막에 한 번.
- 편집은 모아서: 한 장의 여러 수정은 Edit 한 번, 기계적 반복은 짧은 Python 스크립트.
- plan.md의 그림 명세는 좌표·라벨·색 위주로 간결하게(코드를 길게 붙이지 않음).

## 5. 마지막 응답(보고) 형식 — 짧게

```
덱: <묶음 키> <id> / 장수: N / 자동 점검: N건 / 콘솔 오류: N건 / motion·ask: N·N / 완성본: OK|문제
완성본 파일: 차시자료/완성본/<묶음 키>/<folder>.html (크기)
한 일: (5줄 이내)
목표 이행: 목표 N개 모두 (장 번호) / 빠진 것
출처 확인: 사실 N개 중 출처 있음 N, 확인 필요 N
선생님 확인 필요: (항목마다 한 줄, 최대 8개)
엔진·도구 문제: (없으면 "없음")
```
