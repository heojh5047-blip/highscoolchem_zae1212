# 교사 연수 덱 약속

`공통.md`, `docs/슬라이드_제작_가이드라인_범용.md`와 함께 읽는다. 청중은 **동료 교사**다. 교사는 바쁘고, 연수가 끝나면 "내일 학교에서 무엇을 하면 되는가"를 가져가고 싶어 한다. 이 약속은 그것을 화면 구성으로 바꾼 것이다. 덱 plan.md 0절의 "덱 공통 약속"은 이 문서를 따르고 덱에서 새로 정하는 것만 덧붙인다.

## 1. 덱 정보 — 먼저 정할 네 가지

| 항목 | 정할 것 | 예 |
|---|---|---|
| 주제 | 한 문장 | 과학실 사고를 예방하고, 사고가 나면 바르게 대응한다 |
| 대상 | 학교급·교과·경력, 인원 | 중·고 과학 교사 30명(신규·전입 교사 포함) |
| 시간 | 차시 수 × 분 | 2차시 × 50분 |
| 목표 | 끝나고 할 수 있게 될 것 3–4개 (동사로) | 시약장을 점검표로 점검할 수 있다 |

차시가 여럿이면 **차시 하나 = 덱 하나**다. 덱목록.json의 한 묶음 키 아래 차시 순서대로 둔다.

## 2. 세션 구성 (차시 하나)

| # | 부분 | 표식(h2 `tag`) | 시간 비율 | 장 | 하는 일 |
|---|---|---|---|---|---|
| 0 | 표지 + 목표·흐름 | — / `tag alt` 오늘의 흐름 | 3% | 2 | 표지, 목표 3–4개 + 오늘의 흐름(`.flow`에 부분별 분) |
| 1 | **여는 질문** | `tag q` 여는 질문 | 7% | 1–2 | 청중의 경험을 끌어내는 질문 하나(손들기·선택지). 답은 `.step`으로 "오늘 이것을 다룹니다" |
| 2 | **핵심 개념** | `no` 번호 | 25% | 4–6 | 꼭 알아야 할 것 3–5개. 장마다 하나, 정의는 `<mark>`, 근거는 `.small` 출처(S15) |
| 3 | **시연·사례** | `tag ex` 사례 | 15% | 2–4 | 실제 상황 → 질문 → 대응(`.step`). 사례 → 그림 → 정리(S10) |
| 4 | **실습 안내** | `tag` 실습 | 3% | 1 | 번호 단계 3–5개 + 타이머 + 결과물 + 활동지 쪽(S13) |
| 5 | (실습 진행) | — | 25% | 0 | 실습 안내 장을 띄워 둔 채 진행(타이머) |
| 6 | **실습 결과 공유** | `tag` 공유 | 8% | 1–2 | 모둠 발표 순서·질문 틀, 예시 결과(`.step`) |
| 7 | **정리·체크리스트** | `tag ink` 정리 | 5% | 1–2 | 체크리스트(`.chips .chk`) 또는 한 장 요약 |
| 8 | **학교에서 바로 쓰기** | `tag ink` 바로 쓰기 | 4% | 1 | 내일 할 일 3가지, 자료 파일 이름, 함께 쓸 사람 |
| 9 | **Q&A** | `tag q` 질문 | 4% | 1 | 큰 글 "질문"과 미리 모은 자주 묻는 질문 1–3개(`.step` 답) |
| 10 | **설문·자료 안내** | `tag alt` 안내 | 1% | 1 | 설문 주소·자료 위치·연락처 — **선생님이 준 것만**(지어내지 않음). 없으면 자리만 두고 "확인이 필요한 점"에 |

- 비율은 기준이다. 실습이 없는 강의형이면 4–6을 빼고 2·3을 늘리되, 30분에 한 번은 청중이 손·입을 쓰는 활동(질문, 체크, 짝 토의)을 넣는다.
- 2차시 이상이면 둘째 차시 첫머리에 **지난 차시 다시 보기 1장**(`tag alt`)을 두고, 마지막 차시에만 설문 장을 둔다(중간 차시는 "다음 차시 예고").

## 3. 장수 기준

| 연수 시간 | 장수 | 메모 |
|---|---|---|
| 30분 | 10–14장 | 실습 짧게(5–8분) |
| **50분** | **15–20장** | 실습 10–15분 |
| 90분 | 25–35장 | 실습 2회 또는 긴 실습 1회 + 휴식 안내 1장 |
| 3시간 | 덱 2–3개 | 50–60분 단위로 나눈다(덱마다 표지·목표). 쉬는 시간 장 |

장수는 실습 진행 시간을 빼고 센다. 20장을 넘으면 plan.md에 이유를 적는다.

## 4. data-sec·id·표식

| 장 | data-sec 꼴 | 예 |
|---|---|---|
| 표지 | `<묶음 이름> · <N>차시` | `과학실 안전과 교구 관리 · 1차시` |
| 목표·흐름 | `<N>차시 <제목>` | `1차시 실험실 안전 교육` |
| 내용 | `<두 자리 부분 번호> · <부분 이름>` | `02 · 안전 수칙`, `03 · 사고 사례` |
| 실습 | `<번호> · 실습` | `04 · 실습` |
| 끝 | `<N>차시 <제목> · 마무리` | `1차시 실험실 안전 교육 · 마무리` |

- id 접두어: 덱목록 `idPrefix`(예: `ts1-`, `ts2-`). 실험실 이름 `ts1timer`, defs id `grad-ts1-07`.
- 표식 글: 여는 질문, 오늘의 흐름, 사례, 시연, 실습, 공유, 정리, 바로 쓰기, 질문, 안내, 다시 보기. 덱 안에서 같은 이름을 같은 뜻으로.

## 5. 장 만들기 약속

### 5.1 여는 질문
- 질문 하나, 큰 글(32–40px). 선택지가 있으면 카드 2–4개(`.choices`).
- 청중의 학교 경험을 묻는다("우리 학교 시약장에서 라벨이 지워진 병을 본 적이 있나요?"). 답이 정해진 퀴즈보다 경험·의견 질문.
- 다음 누름(`.step`)에 "오늘 다룰 것" 한 줄.

### 5.2 핵심 개념
- 한 장에 하나. 정의·원칙 한 문장(`<mark>`) + 그림 또는 표 + 출처(`.small`).
- **법령·지침·기준을 인용하면 문서 이름·조항·연도를 출처와 대조**하고 화면 아래에 적는다. 선생님이 준 자료에 없는 법령 이름을 기억으로 쓰지 않는다(S15).

### 5.3 시연·사례
- 상황(그림 + 짧은 글) → "Q. 이때 무엇부터 할까요?" → `.step` 대응(번호 순서) → 왜 그 순서인가.
- 실제 사고·민원 사례는 **선생님이 준 사례나 공개된 공식 자료의 사례만**. 학교·사람이 드러나지 않게 다듬는다. 자료가 없으면 "가상 사례"라고 밝힌다.

### 5.4 실습 안내 (S13) — 한 장에 다
```
h2: <span class="tag">실습</span> 시약장 점검표 채우기 (15분)
왼쪽: ol.goals 단계 1–5 (동사로 시작, 한 줄씩)
      결과물: 「점검표 1장 + 고칠 점 1가지」 · 활동지 N쪽
오른쪽: 실습 타이머 (AUTHORING.md 6.1, data-min="15")
아래 .small: 모둠 구성·준비물·주의
```
- **실습 단계 번호**는 활동지 번호와 같게. 활동지가 있으면 화면에 "활동지 N쪽 ②번"처럼 연결하고, 활동지 파일 이름을 plan.md 0절에 적는다(활동지 자체를 만들라는 요청이 없으면 만들지 않는다 — 필요하면 선생님에게 묻는다).
- 타이머는 장마다 `data-min`만 바꿔 쓴다. 실습이 여러 번이면 실습 안내 장마다 타이머.

### 5.5 실습 결과 공유
- 공유 순서(모둠 1 → 2 …)와 발표 틀("우리가 찾은 것 / 고칠 점 / 질문") + 예시 결과(`.step`). 판서 공간(`.board`)을 넉넉히.

### 5.6 정리·체크리스트 (S14)
- 청중이 학교에 가져가 그대로 쓸 수 있는 꼴. 체크 칩은 한 장에 6–10개, 한 칩 한 줄.
- 인쇄(Ctrl+P)해도 보이게 정답·체크 항목을 `.step`에만 숨기지 않는다(체크리스트 자체는 처음부터 보이게).

### 5.7 학교에서 바로 쓰기 (팁 장)
- "내일 할 일 3가지"(번호), "필요한 자료"(파일 이름·쪽), "함께 할 사람"(부장, 실무사, 행정실 등 역할만 — 실명 금지).
- 학교마다 다를 수 있는 것은 "우리 학교 기준을 확인하세요"로 맺는다.

### 5.8 Q&A·설문·자료 안내
- 자주 묻는 질문은 선생님에게 받은 것만, 없으면 plan.md에 후보를 적고 묻는다.
- 설문 주소·QR·연락처는 선생님이 준 것만 넣는다. QR 그림은 선생님이 준 그림 파일(`img/`)로.

## 6. 말투·글

- 동료 교사에게 하는 말투: "~합니다/~하세요", 훈계조("반드시 ~해야만 합니다!") 대신 근거와 함께.
- 화면 글은 짧게: 한 장에 문장 5개 이내, 한 문장 40자 안팎. 말로 할 내용은 plan.md 발표자 메모에.
- 행정 용어·약어는 처음 나올 때 풀어 쓴다(예: "물질안전보건자료(MSDS)").

## 7. 주제별 요소

아래는 주제에 맞게 넣을 요소의 **목록**이다. 구체적인 사실(법령·고시 이름과 번호, 기준 수치, 보관 기간, 절차의 단계, 기관 이름)은 덱을 만들 때 **선생님이 준 자료(교육청 매뉴얼, 학교 규정, 공문, 지침)나 공식 출처에서 확인한 것만** 쓰고 출처를 화면에 적는다. 여기 적힌 것은 "무엇을 다룰지"이지 "사실"이 아니다. 확인하지 못한 것은 plan.md "확인이 필요한 점"에 남긴다.

### 7.1 실험실 안전
| 요소 | 장 꼴 | 확인할 것(출처) |
|---|---|---|
| 안전 수칙 체크리스트 | 체크 칩 2단(실험 전 / 실험 중 / 실험 후) | 학교·교육청 과학실 안전 수칙 원문 |
| 개인 보호구 | 그림 카드(보안경, 실험용 장갑, 실험복 등) + 언제 쓰는가 | 보호구 종류·착용 기준 |
| 사고 사례 → 대응 절차 | 사례 그림 → Q → `.step` 번호 절차(응급 처치 → 보고 → 기록) | 응급 처치 방법·시간(예: 씻는 시간), 보고 순서·서식 — 매뉴얼 원문 |
| MSDS(물질안전보건자료) | 한 장 구조도(항목 이름) + 어디서 찾는가 + 읽기 실습 | 항목 구성·비치 의무 — 관련 법령·지침 원문 |
| GHS 그림 문자 | 그림 문자 표(직접 그린 SVG: 빨간 마름모 테 + 상징) + 뜻 + 예시 시약 | 그림 문자의 종류·이름·코드(예: GHS01–GHS09 꼴)·모양 — 공식 자료와 대조. 코드 낱말은 `data-audit="skip"`(가이드라인 2.3) |
| 시약 라벨 읽기 | 라벨 그림(가상의 시약) + 빈칸 채우기 | 라벨 표시 항목 |
| 비상 연락·대피 | 연락 순서 흐름도(`.flow`) + 과학실 대피 경로 배치도(SVG, 점선 흐름 `dash`) | **학교의 실제 연락처·대피 경로는 선생님이 준 것만**. 없으면 빈칸 꼴(학교에서 채우도록) |
| 소화·응급 장비 | 위치 확인 체크(소화기, 세안기, 샤워, 구급함 등) | 학교 과학실 실제 비치 장비 |
| 폐수·폐기물 처리 | 분류 표(산·염기 / 유기 / 중금속 등 — 자료대로) + 하지 말 것(`plus`) / 할 것(`field`) | 분류 기준·보관·위탁 처리 절차 — 교육청 지침 원문 |
| 실습 예 | 「우리 과학실 안전 점검」(체크리스트로 15분), 「MSDS 찾아 읽기」 | |

### 7.2 교구 관리 (2022 개정 교육과정)
| 요소 | 장 꼴 | 확인할 것(출처) |
|---|---|---|
| 왜 교구 관리인가 | 여는 질문 + 2022 개정 교육과정 탐구 활동과 교구의 연결 | 교육과정 원문(선생님이 준 문서)에서 탐구 활동 예 |
| 교구 목록 | 표(분류 / 교구 / 쓰이는 단원·활동 / 수량) | 학교 교구 목록, 교구 설비 기준이 있으면 그 문서 이름과 번호 |
| 점검표 | 점검표 꼴(항목 / 상태 ○△✕ / 조치) + 실습 | 학교 점검 주기·서식 |
| 구입 절차 | 단계 카드(요구 조사 → 계획 → 품의 → 검수 → 등록 등 — 자료대로) | 학교 물품 관리 규정·행정실 절차 원문 |
| 폐기(불용) 절차 | 단계 카드 + 시약·기기 폐기 구분 | 불용 처리 규정, 폐시약 처리 지침 원문 |
| 시약장 관리 | 시약장 배치 그림(칸별 분류) + 함께 두면 안 되는 것(`plus`) + 잠금·환기 | 분리 보관 기준 — 자료 원문(기억으로 쓰지 않음) |
| 보관·대장 | 대장 꼴(시약 관리 대장, 교구 대장의 열 이름) + 기록 예시(가상) | 학교·교육청 서식, 보관 기간 |
| 디지털 교구 | 센서·기기 목록 + 충전·업데이트·대여 관리 | 학교 보유 기기 |
| 실습 예 | 「교구 점검표 채우기」, 「대장 한 줄 써 보기」, 「불용 품의 순서 맞추기」(카드 정렬 실험실) | |

## 8. 실험실·움직임 쓰임 (연수)

- **실습 타이머**(필수 — 실습이 있는 덱), 체크 칩, 순서 맞추기(단추를 차례로 누르면 단계가 채워짐), 분류하기(시약 카드를 시약장 칸에 넣으면 적합/부적합), 점검표(누를 때마다 ○ → △ → ✕).
- 움직임: 절차 상자가 차례로 나타남(`pop`), 대피 경로 점선이 출구로 흐름(`dash` + `data-flow`), 체크 표시가 그려짐(`draw`). 덱마다 8–15곳.

## 9. 마지막 장
덱 마지막 장은 Q&A 또는 설문·자료 안내다(중간 차시는 "다음 차시 예고"). 연락처를 넣을 때는 선생님이 준 공용 연락처만.
