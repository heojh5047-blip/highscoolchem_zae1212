# 슬라이드 제작 가이드라인 (범용 — 수업·교사 연수·설명회·발표)

이 문서는 고등학교 수업용으로 만들고 실제 수업 피드백으로 다듬은 슬라이드 엔진의 규칙에서 **과목과 상관없는 규칙**만 추린 것입니다. 교사 연수, 교과 수업, 학부모 설명회, 일반 발표 등 어떤 주제의 16:9 HTML 슬라이드에도 씁니다. AI에게 슬라이드 제작을 맡길 때 이 문서를 먼저 읽게 합니다.

- 규칙에는 번호(T1, M2, D8, S1 …)가 붙어 있습니다. 번호는 빌드된 덱 머리 주석, **자동 점검 메시지**와 같습니다(점검이 `[D8]`이라고 알려 주면 이 문서의 D8을 봅니다).
- 원래 묶음의 번호를 그대로 둡니다. 과목 전용 규칙(화학식 C 계열 등)은 「교과 전용」으로 짧게만 남겼습니다.
- **(제안)** 표시는 아직 엔진에 없는 기능입니다. 표시가 없는 것은 `차시자료/_소스/engine`에 이미 있습니다.
- 대상별 세부 약속(장수, 흐름, 표식 이름)은 `차시자료/_소스/작업지시/약속_예시/`의 약속 파일이 정하고, 이 문서는 모든 덱에 공통인 규칙을 정합니다.

## 1. 산출물

| 형태 | 설명 | 쓰는 곳 |
|---|---|---|
| **빌드본** | `차시자료/<묶음 키>/<파일>.html`. 수식 글꼴(KaTeX)·본문 글꼴을 인터넷에서 불러옴 | 만드는 동안 점검·캡처 |
| **완성본** (기본 결과물) | `차시자료/완성본/<묶음 키>/<파일>.html`. 수식·본문 글꼴과 그림이 **파일 하나 안에** 들어 있음 | 선생님이 받아서 두 번 눌러 여는 파일. 인터넷 없는 교실·연수실, USB, 메일 첨부 |

- 덱 하나 = HTML 파일 하나. 서버·설치가 필요 없고 Chrome·Edge·Whale·Safari에서 열립니다.
- 완성본은 보통 1–1.5 MB입니다(그림을 많이 넣으면 커집니다 — 그림 한 장은 500 KB 안쪽으로).

## 2. 핵심 규칙 (하우스 규칙)

엔진이 기본값으로 적용하고, 어기면 **자동 점검**(7장)이 알려 줍니다.

### 2.1 조판 (T)

| 번호 | 규칙 | 구현 |
|---|---|---|
| T1 | 줄바꿈은 **어절 단위**(본문, 표 칸, 목록, 제목 모두) | `word-break: keep-all` + 엔진의 `keepWords()` |
| T2 | **수식은 중간에서 줄이 바뀌지 않음**. 수식 뒤 조사("$x$는")도 떨어지지 않음. 긴 식은 블록(`.formula`)으로 | `.katex{white-space:nowrap}` + WORD JOINER |
| T3 | 여러 식·여러 단계 문장은 **세로로 쌓고** 간격을 둠 | 식이 칸보다 넓으면 1단 배치 |
| T4 | 표 칸은 가능하면 **한 줄**. 넘치면 ① 문장 줄이기 ② 20px ③ 자간 −0.02em 순서 | `table.tight` |
| T5 | 제목 번호와 제목 사이 간격 일정, 제목 글자 사이가 벌어지면 안 됨 | 제목을 flex로 만들지 않음 |
| T6 | 여러 줄로 이어지는 식은 **등호 위치를 맞춤** | `\begin{aligned} … &= … \end{aligned}` |

> T1 주의: CSS만으로는 부족합니다. 인라인 요소 경계(`<mark>핵심 낱말</mark>이다`)에서 브라우저가 줄을 바꿀 수 있어 엔진이 JS로 보정합니다. 수식·빈칸 바로 앞뒤에 **띄어 쓰지 않고 붙인** 조사·괄호는 자동으로 한 덩어리가 됩니다.

### 2.2 수식·기호 (M) — 수식이 있는 덱만

| 번호 | 규칙 | 예 |
|---|---|---|
| M1 | 기호·변수는 LaTeX로. **그림 속 라벨도 LaTeX**(`<text class="tex">`). 유니코드 첨자(₂, ²) 금지 | `$x^2$`, `$a_1$` |
| M2 | 단위의 곱은 `\cdot`. 가운뎃점(·)을 수식 안에 쓰지 않음 | `\text{kg}\cdot\text{m}` |
| M3 | 단위는 **그 양에만**. 식 뒤에 `[단위]`를 붙이지 말고 `.unit` 줄에 | "$v$의 단위: m/s" |
| M4 | 변수는 기울임, 숫자·단위·설명 첨자는 바로 선 글꼴 | $V_\mathrm{A}$, $E_\text{전체}$ |
| M5 | 본문 속 기호 이름도 수식으로 | "점 $\mathrm{A}$와 $\mathrm{B}$" |
| M6 | 수식 안 괄호는 크기를 맞춤 | `\left(\dfrac{1}{2}\right)^{n}` |
| M8 | 곱은 `\times`(알파벳 x 금지), 큰 수·작은 수는 과학적 표기 | $3.0\times10^{8}$ |
| M9 | 수와 단위 사이 한 칸, 단위는 `\text{}` 안에 | `25\ {}^\circ\text{C}`, `10\ \text{분}` |
| M10 | 변화량은 `\Delta`, 처음 값 첨자 0. 덱 안에서 일관 | $\Delta t$, $x_0$ |
| M11 | **상수·기준 값은 plan.md 0절에 한 번** 정하고 덱 전체가 그 값을 씀 | 연수: 실습 시간, 기준 날짜, 수치 기준 |
| M13 | 부호·약속(방향, 양/음의 뜻)은 처음 쓸 때 화면에 밝힘 | "왼쪽에서 오른쪽을 +로 한다." |

수식이 없는 덱(연수·설명회 대부분)은 M 규칙이 거의 쓰이지 않습니다. 숫자와 단위는 일반 글자로 "10분", "3층 과학실"처럼 써도 됩니다.

### 2.3 교과 전용 기호 (선택)

교과 수업 덱에서 그 교과의 표기 약속이 필요하면 **교과수업 약속 파일**에 적습니다. 엔진에 이미 있는 것은 하나뿐입니다.

| 번호 | 규칙 |
|---|---|
| C1 (화학식) | 화학식·이온·반응식은 KaTeX mhchem `\ce{}`로 씁니다: `$\ce{H2O}$`, `$\ce{2H2 + O2 -> 2H2O}$`. 본문 글자 `H2O`, `Na+`는 자동 점검 **C1**이 찾아냅니다. 화학을 다루지 않는 덱에서도 **대문자 뒤에 숫자나 +·−가 붙은 낱말**이 걸립니다(시험해 본 결과: `A4`, `GHS05`, `Q1`, `PM2.5`, `A+`, `K-에듀`는 걸림 / `3D`, `MSDS`, `USB`, `LED`, `Wi-Fi`, `COVID-19`, `Q&A`는 괜찮음) → 그 낱말을 `<span data-audit="skip">GHS05</span>`로 감싸거나 `$\text{GHS05}$`로 씁니다. 안전 연수의 화학 물질 이름은 `\ce{}`를 쓰면 아래 첨자가 바르게 나옵니다. |

### 2.4 도식 (D)

모든 그림은 **직접 그린 SVG**(또는 선생님이 준 그림·직접 찍은 화면 갈무리)입니다. 교과서·인터넷 그림을 복사하지 않습니다(저작권).

| 번호 | 규칙 |
|---|---|
| D2 | **화살표에는 무엇의 흐름인지 라벨**: 순서("1 → 2"), 이동("대피 경로"), 영향("원인 → 결과") |
| D3 | **대칭인 것은 그림도 대칭**: 같은 단계 카드는 같은 크기, 같은 간격 |
| D4 | 그래프 축 라벨은 **기호 [단위]** 또는 "이름 (단위)". 축 화살표·선과 겹치지 않게 |
| D5 | SVG의 `marker`·`gradient`·`clipPath` 등 **id는 덱 전체에서 고유**: 덱 접두어 + 슬라이드 번호(`grad-ts1-07`). 화살표는 marker 대신 `data-arw` |
| D7 | **색 하나 = 뜻 하나**(2.5절). 한 슬라이드 안에서 같은 색이 두 뜻을 가지면 안 됨 |
| D8 | 라벨이 잘리거나 서로 겹치지 않게. 가장자리 라벨은 안쪽으로 |
| D9 | **막대·화살표 길이는 크기에 비례**. 비교하지 않는 그림이면 "크기 비례 아님" |
| D10 | 길이·간격 표시는 치수선(양 끝 화살표 + 가운데 라벨)으로, 윤곽선 바깥에 |
| D11 | ⊗ ⊙ 같은 특수 문자 대신 SVG로 그림 |
| (교과 전용의 예) | D1 회로도(`data-circuit`), D21 입자 모형(`data-atom`), D22 루이스 전자점식, D23 분자 구조 — 원래 화학·물리 묶음의 규칙. 교과 수업 덱에서 쓰려면 엔진 머리 주석과 `AUTHORING.md` 5.3절을 본다 |

**그림 종류별 권장** — 순서도·절차(대응 절차, 구입 절차)는 `.flow` 또는 SVG 상자 + `data-arw`, 비교(전·후, 옳음·그름)는 2열 카드, 배치도(과학실 평면도, 대피 경로)는 단순 SVG(벽·문·통로) + 범례, 표지·장 머리 그림은 주제를 나타내는 단순한 상징 그림.

### 2.6 수업·연수 흐름 (S)

| 번호 | 규칙 |
|---|---|
| S1 | 답·결론·풀이·사례의 결말은 `.step`으로 숨겼다가 **하나씩** 공개. **그림과 그 설명은 같은 단계**(같은 `data-g`) |
| S2 | **문제·과제는 한 장에 하나**. 판서·메모 공간(`.board`)을 남기고 정답 상자는 가운데 정렬 |
| S3 | 과정이 있는 것(절차, 단계, 변화)은 **단계별 그림 카드**(`.stages`)로, 서로 다른 과정은 슬라이드를 나눔 |
| S4 | 슬라이드를 넣거나 나누면 번호가 바뀜 → 보고에 "N번 뒤 +1"처럼 알림 |
| S5 | 새 내용 앞에 **왜 필요한가** 연결 슬라이드(문제 상황 → 그래서 이것) |
| S6 | 오해가 흔한 내용은 **예측 → 관찰 → 설명**: 예측 질문(선택지) → 사례·시연·실험실 → 설명 공개 |
| S7 | 활동·실습 슬라이드는 **목적 → 준비 → 방법(번호 단계) → 결과(표·결과물) → 정리** 순서 |
| S8 | 계산·판단 풀이는 **주어진 것 → 구할 것 → 기준·관계 → 적용 → 확인** 순으로 공개 |
| S9 | **안전**: 실험·실습·시연이 있으면 보호구, 주의 사항, 뒷정리·폐기를 한 줄 이상 |
| S10 | **구체 → 그림 → 기호**: 처음 보는 것은 ① 실제 상황·사례 → ② 그림·도식 → ③ 정리된 규칙·식 순서로 공개 |
| S11 | 디지털 도구·모의실험 활동은 실험실(5.4절)로 대신하거나, 화면 순서·입력값·예시 결과를 단계 공개 |
| S12 | **반드시 이행할 목표**: 덱목록의 `goals`(연수 목표) 또는 성취기준·필수 활동(교과 수업)은 빠짐없이 슬라이드·활동으로 이행하고 plan.md에 대응표를 둠 |
| S13 | **실습 안내 장**: 번호 단계(3–5개) + 시간(타이머) + 결과물 + 활동지 쪽. 실습 중 화면에 계속 띄워 둘 수 있게 한 장으로 |
| S14 | **정리 장**: 체크리스트(`.chips .chk`) 또는 한 장 요약 — 청중이 그대로 가져가 쓸 수 있는 꼴 |
| S15 | **사실은 지어내지 않는다.** 법령·지침·기준의 이름과 조항, 통계, 사고 사례, 날짜, 기관 이름은 선생님이 준 자료나 공식 출처에서 확인한 것만 쓰고, 화면 아래 `.small`에 출처를 적음. 확인하지 못한 것은 plan.md "확인이 필요한 점"에 남기고 화면에는 `[출처 확인 필요]` 표시 없이 넣지 않음 |

## 3. 화면과 레이아웃

### 3.1 무대
- 고정 **1280 × 720** 논리 픽셀 위에 배치하고 창 크기에 맞춰 확대·축소합니다. 프로젝터가 달라도 줄바꿈 위치가 그대로입니다.
- 안전 여백: 위 78px, 좌우 84px, 아래 64px. 위 띠에는 `data-sec`(왼쪽)와 쪽 번호(오른쪽)가 자동으로 들어갑니다.
- 배경은 옅은 32px 모눈입니다.

### 3.2 글자 크기

| 요소 | 크기 |
|---|---|
| 표지 제목 | 120px(길면 줄을 나눔) |
| 슬라이드 제목(h2) | 40px |
| 소제목(h3) | 23–25px |
| 본문 | 24px, 줄 간격 1.6 |
| 보조(.small) | 19px |
| 핵심 문장·공식 상자 | 28–34px |
| 그림 라벨 | 20–24px (화면 기준 최소 16px, 권장 18px) |

**본문은 19px 아래로 내리지 않습니다.** 넘치면 글자를 줄이지 말고 문장을 줄이거나 슬라이드를 나눕니다. 그림 라벨은 SVG가 줄어 보이므로 **무대에서 실제로 보이는 크기**로 잽니다(자동 점검 3.2).

### 3.3 레이아웃 템플릿

| 템플릿 | 구조 | 쓰임 |
|---|---|---|
| 표지 | 큰 제목 + 부제 + 오른쪽 상징 그림 | 덱 시작 |
| 목표·흐름 | `ol.goals` + 오늘의 흐름 `.flow`(시간 표시) | 연수 목표, 수업 목표 |
| 여는 질문 | 큰 질문 한 문장 + 선택지 카드 또는 손들기 | 도입(S6) |
| 개념 | 정의 문장(형광펜) + 핵심 상자 + 보충 | 핵심 내용 |
| 2단 | `.row > .col` 두 개 | 설명 + 그림 |

## 4. 렌더링 순서와 완성본

엔진은 다음 순서로 그립니다(덱 작성자는 알기만 하면 됩니다): ① 번호·단계·목차 → ② 부품(`data-arw`, 실험실 …) → ③ KaTeX(본문 `$…$`) → ④ 그림 속 LaTeX 라벨 → ⑤ 어절 보정 → ⑥ 자동 점검.

- 완성본(`python build.py <덱> --offline`)은 KaTeX CSS·JS·글꼴(woff2)과 **이 덱에 쓰인 글자만 담은 본문 글꼴**을 파일 안에 넣습니다. 본문 글꼴을 받을 때만 인터넷이 필요하고, 받지 못하면 컴퓨터 기본 글꼴로 보입니다(경고가 나옴).
- 완성본 점검 `node verify_offline.mjs <완성본>`: 네트워크를 끊고 열어 **외부 요청 0건, KaTeX 오류 0, 자동 점검 0건**이어야 합니다.
- 그림 파일은 덱 폴더 `img/`에 두고 `src="img/파일.png"`로 쓰면 빌드할 때 파일 안에 들어갑니다.

### 5.1 단계 공개 `.step`
- `.step`은 문서 순서대로 하나씩 나타납니다. **같은 `data-g`**를 가진 것은 함께 나타납니다(그림 속 `<g>`와 설명 `<p>`를 묶음).
- 공개 순서는 각 그룹이 문서에서 처음 나오는 위치로 정해집니다. 순서를 고정하려면 원하는 자리에 빈 `<span class="step" data-g="…"></span>`을 둡니다.
- 다음 키: 숨은 단계 하나 공개, 없으면 다음 장. 이전 키: 마지막 단계 숨김, 없으면 이전 장(모두 펼친 상태).

### 5.2 교과 전용 부품의 예 (짧게)
엔진에는 원래 교과용 부품도 들어 있습니다. 교과 수업 덱에서만 씁니다.
- `data-atom`(원자 모형 — 원소별 색 공), `\ce{}`(화학식), `data-circuit`(회로도), `data-field`·`data-vfield`·`data-bgrid`(전기장·자기장), `.cappanel`(축전기). 쓰는 법은 엔진 머리 주석(`engine/harness.js` 앞부분)과 `AUTHORING.md` 5.3절.
- 루이스 전자점식·분자 구조·그래프·에너지 도표 같은 부품은 **(제안)**입니다 — 지금은 SVG로 직접 그립니다.

### 5.3 그림·화면 갈무리
- 프로그램 사용법 연수처럼 실제 화면이 필요하면 선생님이 준 화면 갈무리를 `img/`에 넣어 씁니다. 개인 정보(이름, 전화번호, 학생 정보)가 찍힌 화면은 쓰지 않거나 가립니다.
- 사진·그림은 출처와 이용 허락을 확인합니다. 확인이 안 되면 직접 그린 SVG로 대신합니다.

### 5.4 실험실 (인터랙티브)
조작 → 계산 → 수치·그림 갱신. 형식 `<div class="lab" data-lab="이름">`, 동작은 덱 `labs.js`의 `window.DECK_LABS.이름(root, API)`.
- 조작부 옆에 **현재 값과 단위**(`output`), 결과는 크게, 해석은 문장으로(`output.kind`).
- 극단값에서도 그림이 칸 밖으로 나가지 않게 상한·로그 척도.
- 움직이는 시뮬레이션은 `API.loop`(슬라이드가 보일 때만 돎), 무작위는 고정 시드.
- 초기화 단추(`data-act="reset"`)를 둡니다.
- 연수·설명회에서 쓰기 좋은 실험실: **실습 타이머**, 점수·체크 집계, 점검표 채우기(누르면 상태가 바뀌는 칸), 조건을 바꾸면 결과가 바뀌는 간단한 모의 상황(예: 보관 조건 고르기 → 적합/부적합). 코드 틀은 `AUTHORING.md` 6절.

### 6.4 움직임
화면이 '살아 있게' 하되 이해를 돕는 움직임만 씁니다.
- **엔진이 자동으로 하는 것**: 장이 보일 때 본문이 차례로 떠오름, 형광펜이 그어짐, `data-arw` 화살표가 자람, 단계 공개 효과, 정답이 한 번 반짝임. 인쇄·캡처·점검·`?still`·'동작 줄이기' 설정에서는 움직임 없이 그대로.
- **그림 움직임 `data-anim`**(내용이 정함). 원칙: **M-A 그린 모습 = 마지막 모습**(움직임은 `data-from`에서 그린 모습으로 옴), **M-B 내용에 맞게**(절차는 순서대로, 흐름은 실제 방향으로 — 장식용 무의미한 움직임 금지, 한 그림에 1–2개, 덱마다 8–20곳), **M-C 라벨은 움직이는 물체와 같은 묶음일 때만 함께 움직임**(끝 모습에서 겹치지 않음).

| 값 | 뜻 | 추가 속성 |
|---|---|---|
| `rot` | `data-from`(°)만큼 돌려 놓은 데서 | `data-o="cx,cy"` 회전 중심 |
| `move` | `data-from="dx,dy"`만큼 옮긴 데서 | |
| `scale` · `pop` | 배율에서 / 작게서 튀어나옴(`"1,0"`이면 세로로 자라는 막대) | `data-o` |
| `fade` · `draw` | 나타남 / 선을 그림 | |
| `spin` · `dash` | 계속 돎 / 점선이 흐름(흐름 방향). 움직일 때만 보일 덧그림에는 `data-flow` | `data-speed` |

공통: `data-dur`(초) `data-delay` `data-rep="once|alt|loop|damp|swing"` `data-ease="io|out|lin|in|soft|back|bounce|sine"` `data-on="step"`(가까운 `.step`이 켜질 때) · `data-on="g:이름"`. 움직일 부분을 `<g>`로 묶어 씁니다. 움직이는 그림은 누르면 다시 움직입니다.
- 연수 덱의 쓰임 예: 절차 상자가 차례로 나타남(`pop` + `data-delay`), 대피 경로 점선이 출구 쪽으로 흐름(`dash` + `data-flow`), 막대그래프가 자람(`scale "1,0"`), 점검표에 체크 표시가 그려짐(`draw`).
- 점검: `node motion_check.mjs <덱>`(움직임 켜고 모든 단계를 넘기며 콘솔 오류 0).

### 6.5 질문 먼저, 답은 다음 누름에
발표자 화면이 없으므로, 답 단계 직전에 **한 번 누르면 질문을 강조**하고 **다음 누름에 답**을 엽니다.
- 엔진이 '답'으로 보는 단계: `.blank` 안 단계, `.ans`/`.answer`, `→`로 시작하는 단계, 점선 빈칸 상자 위의 글, `data-ask`.
- 작성 규칙: **질문 문장에는 '?'를 쓰거나 'Q'로 시작**합니다. '?'가 없는 지시문은 그 요소에 `data-q`. 강조를 빼려면 단계에 `data-ask="no"`.
- 점검: `node ask_check.mjs <덱>` 0건.
